# space-manager — размещение кластеров на пиксельной сетке

**Мастер-бриф проекта.** Этот файл — максимально полное описание задачи и точка
входа в документацию. Он используется для постановки задачи в сессии разработки.

> ⚠️ **Процессное правило (обязательно):** всю работу разбивать на подзадачи и
> делегировать субагентам; субагенты работают **строго по очереди**, оркестратор
> не работает параллельно с субагентом (однопоточный LLM-сервер).
> Подробности: [docs/08-workflow-subagents.md](docs/08-workflow-subagents.md)

## 1. Задача в одном абзаце

Реализовать механизм размещения **замкнутых кластеров** на общем пространстве,
задаваемом прямоугольной «пиксельной» сеткой `W × H`. Каждая ячейка принадлежит
одному из заранее известных типов кластеров (обозначается символом), свободна или
заблокирована. На вход система получает **набор известных типов** и **произвольное
описание желаемых размещений**. Система должна разместить указанные кластеры на
предоставленной площади в соответствии с **правилами размещения** и **принципами
соседства**; при невозможности — сообщить об этом с указанием причины.

Язык реализации: **Python**.

## 2. Ключевые зафиксированные решения (консенсус обсуждения)

1. **Связность/соседство — по 8-окрестности** (ортогональ + диагонали).
2. **Вложенность исключена** на текущем этапе: кластеры могут только *граничить*
   друг с другом. (Матрёшка — будущее расширение.)
3. **Слияния нет:** два соприкасающихся кластера одного типа — два разных объекта.
   Внутренняя модель хранит в ячейке **идентификатор экземпляра**, а не символ.
4. **Соседство — default-open + blacklist:** разрешены любые пары типов, кроме
   перечисленных в `forbidden`; опционально жёсткий whitelist через `allow`.
5. **Площади — доли (в %) от доступной площади F** (F = клетки без блокировок).
   Цели **мягкие**: система приближается к долям, может увеличить/уменьшить;
   «лишнее» при `fillAll` распределяется пропорционально; при недостаче —
   обязательно предупреждение.
6. **Заблокированные пиксели** — отдельным текстовым файлом размера `grid`,
   символ `*`; не входят в базу F (10×10 с углом 2×2 → «100%» = 96 клеток).
7. **Форма кластера:** `free` | `rectangle` | `circle` (≈ клетки в радиусе R от
   целочисленного центра). Приоритет — **выпуклые** формы (мягкое предпочтение,
   метрика — заполненность bounding-box).
8. **Предзаполненная карта:** её кластеры неподвижны, перекрывать нельзя.
9. Достаточно найти **одно** размещение (без множества вариантов).

## 4. Что готово сейчас / что делать в сессии разработки

**Готово (проектная документация):**
- Полное описание задачи и доменная модель.
- Форматы входных файлов (YAML-спекация, маска блокировок, preset).
- Правила размещения и принципы соседства.
- Проектирование солвера и формата отчёта.
- План реализации с разбивкой на подзадачи/этапы.

**Следующее действие в сессии разработки:**
1. Прочитать [07-implementation-plan.md](docs/07-implementation-plan.md).
2. Создать каркас проекта (пакет `space_manager`, `pyproject.toml`, `examples/`, `tests/`).
3. Реализовать подзадачи **строго по очереди через субагентов** в порядке:
   `models.py` → `spec_io.py` → `rules.py` → `report.py` → `solver.py` → `cli.py`
   (см. [08-workflow-subagents.md](docs/08-workflow-subagents.md)).
4. Пройти этапы M1–M4, поддерживая тесты на каждом шаге.

## 5. Открытые уточнения для этапа кодирования

Небольшие решения, сознательно отложенные до реализации (не блокируют старт):
- точная метрика/допуск валидации `circle`;
- порог «существенной недостачи» для предупреждения;
- влияние preset на базу F и целевые площади;
- дефолтный бюджет поиска и параметры CLI.
