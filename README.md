# space-manager — размещение кластеров на пиксельной сетке

**Мастер-бриф проекта.** Этот файл — максимально полное описание задачи и точка
входа в документацию. Он используется для постановки задачи в сессии разработки.

> ⚠️ **Процессное правило (обязательно):** всю работу разбивать на подзадачи и
> делегировать субагентам; субагенты работают **строго по очереди**, оркестратор
> не работает параллельно с субагентом (однопоточный LLM-сервер).
> Подробности: [docs/08-workflow-subagents.md](docs/08-workflow-subagents.md)

## 1. Задача в одном абзаце

Реализовать механизм размещения **замкнутых кластеров** на общем пространстве,
задаваемом прямоугольной «пиксельной» сеткой `W × H`. Каждая ячейка принадлежит
одному из заранее известных типов кластеров (обозначается символом), свободна или
заблокирована. На вход система получает **набор известных типов** и **произвольное
описание желаемых размещений**. Система должна разместить указанные кластеры на
предоставленной площади в соответствии с **правилами размещения** и **принципами
соседства**; при невозможности — сообщить об этом с указанием причины.

Язык реализации: **Python**.

## 2. Ключевые зафиксированные решения (консенсус обсуждения)

1. **Связность/соседство — по 8-окрестности** (ортогональ + диагонали).
2. **Вложенность исключена** на текущем этапе: кластеры могут только *граничить*
   друг с другом. (Матрёшка — будущее расширение.)
3. **Слияния нет:** два соприкасающихся кластера одного типа — два разных объекта.
   Внутренняя модель хранит в ячейке **идентификатор экземпляра**, а не символ.
4. **Соседство — default-open + blacklist:** разрешены любые пары типов, кроме
   перечисленных в `forbidden`; опционально жёсткий whitelist через `allow`.
5. **Площади — доли (в %) от доступной площади F** (F = клетки без блокировок).
   Цели **мягкие**: система приближается к долям, может увеличить/уменьшить;
   «лишнее» при `fillAll` распределяется пропорционально; при недостаче —
   обязательно предупреждение.
6. **Заблокированные пиксели** — отдельным текстовым файлом размера `grid`,
   символ `*`; не входят в базу F (10×10 с углом 2×2 → «100%» = 96 клеток).
7. **Форма кластера:** `free` | `rectangle` | `circle` (≈ клетки в радиусе R от
   целочисленного центра). Приоритет — **выпуклые** формы (мягкое предпочтение,
   метрика — заполненность bounding-box).
8. **Предзаполненная карта:** её кластеры неподвижны, перекрывать нельзя.
9. Достаточно найти **одно** размещение (без множества вариантов).

## 6. LLM-управление генерацией (серия LST)

LLM-агент на сервере сам ведёт цикл «запуск генератора → анализ отчёта → следующий запуск»
по вашему текстовому запросу и в конце передаёт **несколько кандидатов** с комментариями;
выбор делает пользователь. ТЗ — [docs-llm/](docs-llm/README.md).

- **Включение:** создайте `llm.config.json` в корне по образцу [`llm.config.example.json`](llm.config.example.json)
  (провайдеры OpenAI-совместимого API + `defaultModel`). Конфиг перечитывается при каждом запросе
  (hot-reload), ключи наружу не передаются; без конфига строка «LLM не настроен», остальное работает как раньше.
- **Где в UI:** редактор (`/editor?project=<slug>`), раздел **«LLM-генерация»** в панели Файлы
  рядом с кнопкой «⚡ Генерировать размещение» (которая остаётся без изменений).
- **Лимиты прогона** (поля в панели, пусто = дефолт): `maxIterations` = 5 (запусков + коррекций),
  `timeBudgetPerRun` = 2.0 с (`--time-budget` каждого запуска). Жёсткого ограничения по времени больше нет:
  прогон завершается, когда модель вызывает `finish`, либо автоматически при стагнации —
  3 подряд одинаковых шага без прогресса (в журнале появляется `note`; если result-файлов нет — статус `stopped`).
- **Что LLM может менять:** только `seed`, `timeBudget`, `nodeBudget` и `areaPercent`
  (±10 % от цели кластера, одноразовая временная копия спеки); коррекция результата — только **новым**
  result-файлом на основе существующего, обязательна валидация `python -m space_manager validate`.
- **Новые маски LLM:** `create_blockages_file` (доступен, только если пользователь не задавал маску
  блокировок) создаёт новый файл `blocked-llm-<ts>.txt`, а `create_preset_file` — `preset-llm-<ts>.txt`
  (в ответе — связные области regions); дальнейшие запуски идут с этими масками через опциональные
  аргументы `run_generation`: `blockagesFile` / `presetsFile`.
- **Что LLM НЕ может:** менять спеку проекта (сетка, типы, формы, правила), маски блокировок/preset,
  `fillAll`/`touchAll`, удалять или перезаписывать существующие файлы проекта.
- **Журнал сессий:** `workspace/<slug>/llm-sessions/<YYYYMMDD-HHMMSS>.json`
  (шаги, лимиты, кандидаты, recommended); история — в той же панели и через API `/api/projects/:p/llm-sessions`.
- **Сырые ответы модели:** каждый шаг журнала хранит дословный ответ модели (поле `raw`,
  усечение 8000 символов) — виден в истории LLM-сессий редактора как раскрывающийся блок «сырой ответ»;
  удобно для отладки локальных моделей.
- **Общий список типов:** каталог хранится в `workspace/types-catalog.json` (API `/api/types-catalog`),
  пополняется автоматически при сохранении спеки/импорте проекта. В панели «Типы» редактора — секция
  «Общий список типов» (чекбоксы): отмеченный тип попадает в спеку проекта и становится доступен
  в селекторе кластера; снять отметку нельзя, пока тип привязан к кластеру.
- **Сеть:** сервис слушает `0.0.0.0` (доступ с других машин); переопределение — env `HOST`
  (например `127.0.0.1`).
