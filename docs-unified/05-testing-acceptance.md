# 05. Тестирование и критерии приёмки

> Сводный индекс: [../docs-unified/README.md](./README.md) · API:
> [02-workspace-api](./02-workspace-api.md) · Интеграции: [04-integrations](./04-integrations.md)

## 1. Общие подходы

- Стек тестов — тот же, что в компонентах: **vitest** (unit/integration) +
  **Playwright** (e2e). Браузер e2e — Chromium.
- API тестируется против **tmp-workspace**: `SPACEMGR_WORKSPACE` указывает на
  `fs.mkdtempSync(os.tmpdir()+…)`; сервер создаётся через экспортированный
  `createApp(workspaceDir, pythonBin)` (чистая функция без listen) + supertest-подобный
  прямой вызов обработчиков ИЛИ слушание на эфемерном порту (`listen(0)`). **Решение:**
  `listen(0)` + fetch — ближе к prod и покрывает mount'ы статики.
- E2E редактора/viewer3d — с моками API через `page.route('/api/**')`: их vite/serve
  не требует запущенного единого сервиса; реальный сервер нужен только сквозному
  e2e (§4).
- Детерминизм: времена в именах файлов в тестах подставляются фиксированными
  (инъекция `now` в хелперы имён — паттерн `cli.py::default_result_name(now=…)`);
  реальные генерации в unit не выполняются (stub-python, §3.4).

## 2. Unit-тесты UI-компонентов новых/изменённых панелей

| Объект | Что проверяется |
|---|---|
| `app/src` — CreateProjectForm | валидация slug (красные: `Abc`, `a b`, 41 символ, `..`; зелёные: `a`, `abc_1-2`), отправка тела `{name}`, отображение 409 |
| `app/src` — ProjectCard/PreviewModal | рендер метрик, кнопки, открытие модалки по клику на миниатюру, закрытие по Esc (jsdom + @testing-library/react, паттерн viewer3d) |
| `editor` ProjectFilesPanel (интеграционный, jsdom) | выбор проекта → dispatch SPEC_LOADED/MASK_LOADED из мок-ответов; нормализация имён масок при загрузке (спека со ссылкой на `blocked_basic.txt` → в модели `blockedFile: 'blocked.txt'`, файл читается по исходному имени); dirty → кнопка сохранения активна с ●; успех save → markClean |
| `viewer3d` ProjectPanel (jsdom) | выбор проекта+ревизии → REPORT_LOADED со `projectName/resultName`; ошибка parseReport → баннер, состояние не сбросилось |

## 3. Unit/integration-тесты API (`app/tests/unit/`)

Все тесты — с tmp-workspace и моковым «python». Таблица ключевых кейсов:

### 3.1 CRUD проектов
| Кейс | Ожидание |
|---|---|
| create → структура на диске | каталог + 4 файла; `spec.yaml` побайтово = эталон [02](./02-workspace-api.md) §4.1; маски = 20×20 точек с `\n`; `project.json` валиден, `latestResult: null` |
| create с плохим именем / дубликат | 400 `INVALID_NAME` / 409 `PROJECT_EXISTS`, каталог не создан |
| list | порядок updatedAt desc; метрики sizeBytes/resultsCount/previewsCount/filesCount верны |
| rename | каталог переименован, json обновлён; коллизия → 409, старый на месте |
| delete | каталог удалён полностью (включая preview/); повторный delete → 404 |

### 3.2 Файлы
| Кейс | Ожидание |
|---|---|
| GET file spec.yaml / result-* | 200, тело = содержимое; `Content-Type` по расширению |
| GET file traversal: `?name=../app/package.json`, `?name=..%2F..%2Fx`, `?name=.hidden` | 400/404, ничего не читается |
| PUT files (3 файла) | записаны побайтово; updatedAt обновлён |
| PUT files без preset.txt при существующем файле | `deleted: ["preset.txt"]`, файл удалён с диска |
| PUT files с чужим именем (`result-x.txt`, `../x`) | 400, ничего не записано |

### 3.3 Генерация (stub-python)
Stub — bash-скрипт в tmp: читает argv, пишет файл из `--out` фиксированным текстом
отчёта, завершается кодом из env/файла-управления.
| Кейс | Ожидание |
|---|---|
| exit 0 | 200 `{resultFile, exitCode:0, feasible:true, report}`; файл создан в каталоге проекта; `latestResult` обновлён; аргументы spawn: `-m space_manager place <abs spec> --out <abs result>` |
| exit 1 (infeasible-отчёт) | 200, `feasible:false`, `report` содержит «НЕ УДАЛОСЬ РАЗМЕСТИТЬ ВСЕ КЛАСТЕРЫ.»; файл создан; latestResult обновлён |
| exit 2 | 422 `SOLVER_INPUT`, message = stderr stub'а; файла результата НЕТ; latestResult не изменился |
| timeout (stub `sleep 70`) | 504 `SOLVER_TIMEOUT` за ~60 с (в тесте — уменьшенный лимит через параметр createApp, дефолт 60 с); частичный файл stub'а удалён; процесс не живёт |
| коллизия имён (два запуска «в ту же секунду» — фиксированный now) | второй файл с суффиксом `-1` |

### 3.4 Архив и импорт
| Кейс | Ожидание |
|---|---|
| archive проекта {spec, blocked, preset, 2×result, preview/2 png, project.json} | zip содержит ровно: spec.yaml, blocked.txt, preset.txt, 2 result-*; НЕ содержит project.json, preview/*; `Content-Disposition` = `<name>-<ts>.zip` |
| import плоского архива со spec.yaml + масками + result | 201, файлы на диске, latestResult из импортированных; `skipped` пуст |
| import архива с одной корневой папкой | префикс снят, имя проекта = имя папки |
| import без spec.yaml | 400 `BAD_ZIP`, каталог не создан |
| import с записью `../../evil.txt` | 400 `BAD_ZIP`, на диске вне workspace ничего не появилось |
| import в занятое имя без ?name= | создан `<base>-2` |

### 3.5 Preview
POST → файл в preview/ (каталог создаётся), 201 с именем; коллизия → суффикс;
GET previews — порядок desc; GET preview?file= — байты 1:1, `image/png`; чужое имя → 400.

## 4. Сквозной e2e-сценарий (Playwright, единый сервер)

Запуск: webServer = `npm start` в `app/` c env `SPACEMGR_WORKSPACE=<tmp>` и
`PORT=3212` (отдельный порт, как у viewer3d e2e); **настоящий** `.venv/bin/python`
(реальный солвер — он быстрый на шаблонах, < 5 с).

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `/` → создать проект `e2e-demo` | карточка появилась; на диске: 4 файла шаблона |
| 2 | перейти по [Редактор] | URL `/editor?project=e2e-demo`; спека загружена (W×H = 20×20), ошибки валидации — НЕТ |
| 3 | поставить кистью 1–2 blocked-клетки, добавить второй кластер (через существующий ClustersPanel) | dirty ● на «Сохранить в проект» |
| 4 | [Генерировать размещение] | спиннер; блок результата: зелёная строка с `result-<ts>.txt`; ссылка Viewer3D |
| 5 | проверка диска (node-assert в тесте) | файл существует; его текст = stdout-отчёту (секции КАРТА/ТАБЛИЦА/ПРЕДУПРЕЖДЕНИЯ); `project.json.latestResult` = имя файла |
| 6 | открыть ссылку Viewer3D | URL `/viewer3d?project=e2e-demo&result=<f>`; комната(ы) отрисованы (canvas не пустой), в списке комнат ≥ 1 |
| 7 | переключить ревизию (сгенерировать вторую из редактора, вернуться) | селектор показывает 2 файла; смена → сцена перестроена (число/площадь комнат по отчёту) |
| 8 | [PNG] в viewer3d | POST preview выполнен; в менеджере на карточке миниатюра появилась |
| 9 | клик по миниатюре | модалка с картинкой оригинального размера; Esc закрывает |
| 10 | [⬇ Архив] (intercept-скачивание) | zip распаковывается: spec.yaml + маски + ОБА result-*; нет project.json и preview/ |
| 11 | импорт скачанного архива в менеджере | новый проект создан, его спека идентична исходной; генерация в нём проходит (exit 0) |

## 5. Приёмочный чек-лист ручной (заказчик)

1. `npm start` в app/ → :4080: три UI открываются, консоль браузера без ошибок.
2. Создание/переименование/удаление проекта — синхронно с диском (`ls workspace/`).
3. Редактор: шаблон открывается без ошибок; блокировка клеток кистью; сохранение;
   генерация (успех и infeasible — сломать спеку, напр. Σ долей > 100 → exit 2 →
   баннер с причиной).
4. Viewer3d: ревизии переключаются; снапшоты копятся в `preview/` и видны в менеджере.
5. Архив проекта скачивается, распаковывается, реимпортируется без потерь.
6. Остановка сервера → редактор показывает баннер недоступности API (не белый экран).

## 6. Чек-лист реализации (помимо кода)

1. `.gitignore` корня: добавить строку `workspace/`.
2. `editor/vite.config.ts`, `viewer3d/vite.config.ts`: base + proxy на :4080.
3. Сборка всех трёх dist до первого запуска prod (`npm run build`).
4. Пересборка editor/viewer3d после правок (их e2e прогоняются на prod-сборке).

## 7. NFR, лимиты и переносы в v2

| Пункт | Значение v1 |
|---|---|
| Размер загрузки (файл/zip) | 10 МБ (413 `PAYLOAD_TOO_LARGE`) |
| Timeout генерации | 60 с (504); очередь — одна активная на проект |
| Число проектов/ревизий | не ограничено; списки без пагинации (локальный режим) |
| Производительность API | list/files/results < 50 мс при ≤ 100 проектах и ≤ 200 ревизиях (замер в unit-тесте с порогами) |
| Архив | сборка < 2 с для проекта ≤ 100 МБ (ручной замер, чек-лист §5.5) |
| v2 | параметры солвера в UI; авто-очистка осиротевших масок; устаревание ревизий; пагинация/поиск проектов; просмотр result в менеджере |

## 8. Открытые решения (на решение оркестратора)

1. **Порт e2e единого сервиса** выбран **3212** (порт e2e viewer3d 3210 занят его собственной серией тестов)
   любой свободный, фиксируется в `playwright.config.ts`.
2. **`filesCount` в `GET /api/projects`** ([03](./03-manager-ui.md) прим. 1): добавляется
   в v1 одним полем (дешёво, один readdir уже считается для sizeBytes).
3. **Реальный солвер в сквозном e2e**: зависит от наличия `.venv`; при отсутствии —
   e2e пропускается с явным сообщением (skip), а не падает (паттерн «автопропуск»
   из viewer3d-интеграций). Дефолт — выполнять, т.к. venv в проекте есть.
