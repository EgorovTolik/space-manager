чтобы smoke не зависел от порядка). При отсутствии `.venv/bin/python` файл пропускается
с явным сообщением (ТЗ 05 §8 п.3), а не падает.

## 3. Найденные баги и корневые исправления

1. **Playwright-конфиг стирал workspace после старта сервера.** `rmSync` выполнялся при
   импорте `playwright.config.ts`, а Playwright импортирует конфиг также в каждом
   test-worker'е — после запуска webServer. Симптом: `ENOENT mkdir …/e2e-demo` на первом
   запросе. Исправлено: очистка вынесена в `globalSetup` (один раз, до webServer),
   конфиг и хелпер пути — без side-эффектов.
2. **Сервер падал ENOENT, если каталог workspace удалён извне после старта** (до рестарта
   все проектные эндпоинты 500). Исправлено в корне: middleware `ensureWorkspace` на
   каждый `/api`-запрос (ленивое восстановление, lstat — дёшево).
3. **Редактор: поля W×H оставались пустыми при загрузке проекта** (`useState('')` без
   синхронизации со спекой). Исправлено: эффект синхронизирует поля с `spec.grid` по
   ключам «выбранный проект + размеры сетки» — обычные правки кластеров введённый,
   неприменённый текст не сбрасывают.
4. **Viewer3D: клик [PNG] в первые мгновения после (пере)загрузки сцены терялся молча.**
   R3F `<Canvas>` монтируется асинхронно — обработчик снапшота регистрируется в эффекте
   ПОСЛЕ первого кадра; до этого `takeSnapshot()` возвращал null без какой-либо реакции
   UI. Воспроизводилось стабильно при быстрой смене ревизии → клике (flake ~1 из 5).
   Исправлено в корне, три уровня:
   - `takeSnapshot({ waitForHandlerMs = 500 })` — ограниченное ожидание регистрации
     обработчика (поллинг ~32 мс) вместо немедленного null;
   - в обработчике кадра: повторная попытка `toBlob` после следующего rAF и видимый
     баннер ошибки (`snapshotFailed`) вместо молчания, если кадр так и не снялся
     (ТЗ 04 §2.4: результат всегда отражается в статусе/баннере);
   - e2e ждёт реальный отрисованный кадр (polling пикселей) до клика [PNG].

## 7. Замечания для v2

- Имя ревизии `result-<ts>.txt` при двух генерациях в одну секунду получает суффикс
  `-1`, который в лексикографическом порядке («desc = свежая первая») уходит **ниже**
  базового имени: «свежей» по списку становится хронологически старшая ревизия.
  В v2 — монотонная нумерация или мtime-сортировка `GET …/results`.
- Клик [PNG] в окне до готовности сцены теперь показывать баннер ошибки; при желании —
  отключать кнопку, пока сцена не готова (в v2).
