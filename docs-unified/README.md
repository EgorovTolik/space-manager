## 1. Цель

Объединить три уже реализованных и протестированных компонента в **один цельный
веб-продукт** — единый сервис с общим рабочим пространством проектов:

| Компонент | Директория | Статус | Роль в объединённом продукте |
|---|---|---|---|
| Генератор размещения (Python-солвер) | `space_manager/` + `.venv/` | готов, **не изменяется вообще** | выполняется как CLI из сервера единого сервиса по кнопке «Генерировать размещение» |
| Редактор входных файлов | `editor/` | готов | адаптируется в **проектный режим**: файлы проекта загружаются с сервера, сохраняются на сервер; standalone-режим «загрузил — скачал» заменяется полностью |
| 3D-визуализатор | `viewer3d/` | готов | адаптируется: вместо загрузки файла — **селектор проекта и селектор ревизий `result-*`**; PNG-снапшот сохраняется в проект как «предпросмотр вида» |
| Менеджер проектов (новый) | `app/` (UI + API) | **реализуется** | точка входа продукта: создание/переименование/удаление проектов, импорт из zip, скачивание архива проекта, галерея предпросмотров |

Принцип реализации: **не переписывать и не переносить** существующие проекты —
только точечная адаптация их страниц/клиентов под проектный режим (что именно
меняется — [04-integrations](./04-integrations.md)). Вся новая серверная логика
живёт в новом каталоге `app/`.

## 2. Зафиксированные вводные заказчика (приняты без обсуждения)

1. **Единый сервис** — новый каталог `app/`, Express, порт **4080**. Раздаёт:
   `/` → UI менеджера проектов (новое небольшое React SPA), `/editor/*` → статика
   `editor/dist`, `/viewer3d/*` → статика `viewer3d/dist`. Файлы существующих
   проектов не переносим.
2. **Рабочее пространство** — общая директория на диске `<root>/workspace/`
   (добавляется в `.gitignore`); проект = поддиректория с файлами проекта и
   служебным `project.json`. Все компоненты работают только с этим пространством.
3. **Генерация не вызывается вручную**: кнопка «Генерировать размещение» в
   редакторе запускает существующий CLI солвера через сервер; Python-код не
   изменяется ни на строку.
4. **viewer3d переключается между ревизиями**: селектор `result-*` файлов проекта;
   кнопки скачивания файлов у viewer скрыты (скачивание — только в менеджере
   проектов, архивом).
5. **Менеджер проектов** — отдельный веб-интерфейс: управление проектами
   (папками на диске) и скачивание проекта одним zip-архивом (сервер собирает все
   файлы проекта **кроме служебных**: `project.json` и поддиректории `preview/`).
6. **Шаблон нового проекта** — при создании через веб сервер создаёт директорию со
   скелетом: `project.json` + валидный `spec.yaml` (20×20, один тип, один кластер
   на 100%) + непустые `blocked.txt`/`preset.txt` (полные сетки `.`) — см.
   [02-workspace-api](./02-workspace-api.md) §4.
7. **История генераций**: каждый запуск создаёт НОВЫЙ файл `result-<ts>.txt`;
   архив включает все результаты.
8. **PNG-снапшоты viewer3d** сохраняются в поддиректорию проекта `preview/`
   (фича «сохранение вида визуализации»), отображаются миниатюрами в менеджере с
   модальным просмотром в оригинальном качестве; в архив НЕ включаются.
9. **Генерация синхронная**: кнопка «занимается» до завершения (hard timeout 60 с);
   infeasible-результат солвера — это **успешный ответ API**, а не ошибка.
10. UI на русском, десктоп Chrome/Firefox/Safari, одноместный локальный сервис без
    аутентификации; единый визуальный стиль панелей (системные шрифты, те же
    паттерны «панель/кнопка/баннер», что в editor и viewer3d).

## 3. Не цели (out of scope)

- Изменения Python-пакета `space_manager/` (исходники, CLI, отчёт) — нет.
- Перенос/переупаковка исходников `editor/` и `viewer3d/` — нет; допускается только
  адаптация, перечисленная в [04-integrations](./04-integrations.md).
- Аутентификация, роли, мультиюзер, конкурентное редактирование — нет.
- Редактирование файлов `result-*` и `preview/*` из браузера (только чтение/создание) — нет.
- Мобильные интерфейсы; локализация кроме русского — нет.
- Параметры солвера в UI (`--seed`, `--time-budget`, `--node-budget`) — v2
  (см. [05](./05-testing-acceptance.md) §7).

## 4. Как запускать (итоговый пользовательский сценарий)

```bash
# сборка фронтендов (по одному разу после изменений):
cd editor   && npm install && npm run build     # → editor/dist
cd viewer3d && npm install && npm run build     # → viewer3d/dist
cd app      && npm install && npm run build     # → app/dist

# запуск единого сервиса:
cd app && npm start          # http://localhost:4080
```

Дальше пользователь работает только с `http://localhost:4080`: менеджер проектов на
главной, редактор — `/editor`, визуализатор — `/viewer3d`. Dev-режимы (vite-серверы
5175/5173/5174 + API 4080) описаны в [01-architecture](./01-architecture.md) §5.

## 5. Сводные критерии приёмки проекта

Подробности и декомпозиция — в [05-testing-acceptance](./05-testing-acceptance.md).

1. `GET /api/health` → `{"status":"ok",...}`; сервис на :4080 раздаёт все три UI.
2. Создание проекта через веб → на диске появилась `workspace/<name>/` с `project.json`,
   `spec.yaml`, `blocked.txt`, `preset.txt`; шаблон открывается в редакторе **без
   ошибок валидации** и успешно генерируется (exit 0).
3. Редактор: выбор проекта → файлы загружены; правка → «Сохранить в проект» пишет
   файлы на диск; «Генерировать размещение» создаёт `result-<ts>.txt` и показывает
   результат (успех / infeasible с причиной).
4. viewer3d: выбор проекта и ревизии `result-*` → 3D-сцена; переключение ревизий
   подгружает выбранный файл; PNG-снапшот появляется в `preview/` и в галерее менеджера.
5. Менеджер: переименование, удаление (директория исчезает с диска), импорт zip →
   новый проект, «Скачать архив» → zip со ВСЕМИ файлами проекта кроме
   `project.json`, `preview/` и самих архивов.
6. Все unit/e2e-тесты трёх компонентов + нового API зелёные; сквозной e2e-сценарий
   «проект → редактор → генерация → viewer3d → снапшот → архив» пройден.

## 6. Словарь

| Термин | Значение |
|---|---|
| **workspace** | директория `<root>/workspace/` — корень рабочего пространства |
| **проект** | поддиректория `workspace/<name>/` с файлами проекта и `project.json` |
| **редактируемые файлы** | `spec.yaml`, `blocked.txt`, `preset.txt` (имена канонические) |
| **ревизия / результат** | файл `result-<ts>.txt` — отчёт одного запуска солвера |
| **предпросмотр (preview)** | PNG-снапшот 3D-вида в `preview/`, имя `preview-<ts>.png` |
| **slug** | допустимое имя проекта: `[a-z0-9_-]{1,40}` |
