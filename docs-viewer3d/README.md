> Точка входа в ТЗ. Остальные документы: [01-architecture](./01-architecture.md),

> Версия: 1.0 · Дата: 2026-09-13. Проект: **space-manager** (см. `../README.md`).

## 1. Цель

Реализовать автономный веб-инструмент **viewer3d**, который по **отчёту размещения
солвера** (`result-<timestamp>.txt`, формат — `space_manager/report.py`) строит
интерактивную **трёхмерную модель окружения**: каждый кластер отчёта представляется
как помещение (комната) с цветным полом, помещения отделены друг от друга и от
свободного пространства **стенами конечной толщины** (экструдированные объёмы, не
линии). Модель можно рассматривать со всех сторон орбитальной камерой.

Сценарий пользователя: **загрузил файл отчёта → смотрит 3D**. Файл редактируется НЕ
будет; генерация/пересчёт размещения инструментом НЕ запускается (вход — готовый
результат).

Редактор входных файлов (`editor/`, ТЗ `docs-editor/`) и подсистема генерации данных —
отдельные компоненты общей системы; viewer3d с ними **не взаимодействует** в runtime.
Единственная формальная граница — **текстовый формат отчёта** `space_manager`
(контракт зафиксирован в [02-input-parser](./02-input-parser.md) §1).

## 2. Состав системы

| Компонент | Технология | Роль |
|---|---|---|
| Фронтенд (SPA) | React + Vite + TypeScript + three.js (@react-three/fiber, @react-three/drei) | парсинг отчёта, геометрия стен, 3D-сцена, панели UI на русском |
| Бэкенд | Node.js + Express | раздача собранного фронтенда, `GET /api/health`. Хранения файлов нет |

Подробности: [01-architecture](./01-architecture.md).

## 3. Зафиксированные вводные заказчика (приняты без обсуждения)

1. **Входной файл — результат размещения**: отчёт `result-*.txt`, генерируемый
   `python -m space_manager place <spec.yaml> --out FILE`. Система **парсит отчёт**
   (секции «КАРТА» и «ТАБЛИЦА»), спекация YAML не требуется.
2. **Стены без проёмов**: на текущем этапе — только стены, дверей/проёмов нет.
   Стена — визуально отличимый объём **умеренной толщины** (не линия). Высота стен
   одинаковая для всех кластеров и настраивается. Цель v1 — разделить кластеры на
   площади; высота — параметр, «несущий» смысл вторичен.
3. **Масштаб настраиваемый**: параметр «1 клетка = N единиц» (дефолт N = 1); единица
   измерения произвольная (подпись по умолчанию «м»). Высота/толщина стен задаются в
   тех же единицах.
4. **Стек и форма**: отдельный веб-сервис `viewer3d/` — Vite + React + TypeScript +
   three.js (@react-three/fiber, @react-three/drei); standalone «загрузил файл →
   смотри 3D», без БД; Express только статика + health (тот же паттерн, что
   `editor/server/index.ts`). Десктоп, UI на русском.
5. **Функционал v1** (согласован): орбитальная камера со всех сторон + пресеты видов;
   пол комнаты цветом типа с подписью; стены-боксы с толщиной/высотой (геометрия:
   граничные рёбра → склейка коллинеарных сегментов, угловые стыки без зазоров);
   прозрачность/скрытие стен; клик по комнате → подсветка + инфо (имя, тип, клеток,
   площадь); экспорт снапшота PNG.
6. **Параметры UI**: загрузка файла; числовые параметры (масштаб, высота, толщина,
   показать blocked); список комнат с площадями и выбором (клик — фокус камеры +
   подсветка); сброс параметров.
7. **Тесты и приёмка**: vitest для парсера и модуля геометрии (чистые TS, без DOM);
   e2e Playwright; приёмочный тест на реальном отчёте `spec_basic.yaml --seed 7`
   (3 комнаты: 650 / 375 / 225 клеток). Лимиты v1: сетка ≤ 200×200, комнат ≤ 128.

## 4. НЕ цели (out of scope, v1)

- Двери/проёмы в стенах, различная высота стен по комнатам — нет (вводная №2;
  roadmap: [05-testing-acceptance](./05-testing-acceptance.md) §8).
- Запуск/пересчёт солвера, загрузка спеки YAML, редактирование отчёта — нет.
- Взаимодействие с `editor/` и подсистемой генерации данных — нет (§1).
- Хранение на сервере между сессиями, БД, auth/мультиюзер — нет (вводная №4).
- Экспорт 3D-модели (GLB/OBJ), наклонные стены, анимации камеры — нет (roadmap §8).
- Мобильные/сенсорные интерфейсы; локализация кроме русского — нет.

## 6. Критерии приёмки проекта целиком (сводка)

Подробности: [05-testing-acceptance](./05-testing-acceptance.md).

1. **Парсинг**: реальный отчёт `spec_basic.yaml --seed 7` разбирается без ошибок;
   комнаты = {650, 375, 225} клеток с метками из таблицы (`room1`, `room2`,
   `corridor1`) ([02](./02-input-parser.md) §6).
2. **Геометрия**: стены образуют замкнутый контур вокруг каждой комнаты и по внешнему
   периметру; автоматический инвариант «100% граничных рёбер комнаты покрыты боксами
   стен» проходит для эталонных фикстур ([03](./03-wall-geometry.md) §7,
   [05](./05-testing-acceptance.md) §5).
3. **UI**: все панели и интеракции [04](./04-ui-interaction.md) работают по описанию;
   параметры с дефолтами из таблицы 04 §3; PNG-снапшот скачивается.
4. **Производительность**: сетка 200×200 — плавный orbit (> 30 FPS), пересчёт стен
   при смене параметров < 100 мс ([05](./05-testing-acceptance.md) §7).
5. **Тесты**: unit (Vitest) и e2e (Playwright) зелёные по наборам [05](./05-testing-acceptance.md) §2–§4.
6. **Запуск**: `npm run build && npm start` открывает viewer в браузере; dev-режим
   `vite + express` работает ([01](./01-architecture.md) §6).

## 7. Словарь

| Термин | Определение |
|---|---|
| клетка | единица сетки отчёта; координаты `(x, y)`, `x ∈ [0..W)`, `y ∈ [0..H)` (строки карты — по Y сверху вниз) |
| кластер / комната | связный компонент (4-связность) одинаковых символов на карте отчёта; в 3D — помещение с полом и стенами ([02](./02-input-parser.md) §3) |
| тип / symbol | тип кластера из реестра спеки; на карте рисуется одним уникальным символом (`space_manager/spec_io.py`: символ = ровно 1 код-поинт, уникален в реестре) |
| blocked | заблокированная клетка, символ `*`; опционально рисуется тёмным блоком ([03](./03-wall-geometry.md) §8) |
| отчёт | текстовый файл результата CLI: секции КАРТА / ТАБЛИЦА / ПРЕДУПРЕЖДЕНИЯ ([02](./02-input-parser.md) §1) |
| стена | бокс (экструзия) вдоль граничного ребра комнаты; толщина T, высота Hw ([03](./03-wall-geometry.md)) |
| S | масштаб: мировые единицы на одну клетку (дефолт 1) |
| Hw / T | высота / толщина стены в мировых единицах (дефолты 3 / 0.25) |
