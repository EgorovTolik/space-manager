## 1. Формат отчёта (контракт)

Источник истины — `space_manager/report.py` (`build_report`, `render_grid`,
`format_table`) и `space_manager/cli.py::_place`. Ниже — полевой контракт, который
парсер реализует **строго**; любые расхождения с реальным файлом — ошибки/предупреждения
из §5 (не «улучшения» формата).

### 1.1 Структура файла

Файл = `report_text + "\n"` (последний перевод строки добавляет CLI). Текст
`report_text` — секции, склеенные **ровно двумя** переводами строк (`"\n\n"`):

```
[блок невозможности — только если размещение не удалось; см. 1.4]

== КАРТА ==
<строка карты y=0>
<строка карты y=1>
...
<строка карты y=H-1>

== ТАБЛИЦА: запрошено / фактически / отклонение ==
id | type | доля (%) | цель (клеток) | факт (клеток) | отклонение | статус
------------------------------------ ...
<строки кластеров>

== ПРЕДУПРЕЖДЕНИЯ ==
<текст предупреждений или «нет»>
```

Требования к точности:

| Элемент | Формат (byte-level) |
|---|---|
| Заголовок карты | строка ровно `== КАРТА ==` |
| Заголовок таблицы | строка ровно `== ТАБЛИЦА: запрошено / фактически / отклонение ==` |
| Заголовок предупреждений | строка ровно `== ПРЕДУПРЕЖДЕНИЯ ==` |
| Карта | H строк, каждая **ровно W код-поинтов**; без завершающих пробелов; между строками `\n`; пустая строка после заголовка и перед следующей секцией (следствие склейки `"\n\n"`) |
| Таблица | 1-я строка — шапка `id | type | доля (%) | цель (клеток) | факт (клеток) | отклонение | статус`; 2-я — разделитель из `-` и ` | `; далее по строке на кластер. Разделитель колонок — ровно ` | ` (пробел-вертик-пробел); колонки выровнены `ljust`, строка обрезана справа (`rstrip`). **Колонка `type` содержит type_id из реестра (НЕ символ карты).** Доля preset-кластера — `—` (em-dash). Цели/факт — десятичные целые |
| Предупреждения | произвольный текст или ровно `нет`; многострочные предупреждения возможны (2 строки в `area_warnings`) |
| Кодировка | UTF-8 |

**Пример реального файла** (фрагмент; полный пример — фикстура
`viewer3d/tests/fixtures/report_basic.txt`, генерация:
`.venv/bin/python -m space_manager place examples/spec_basic.yaml --seed 7 --out report_basic.txt`):

```
== КАРТА ==

RRRRRRRRRRRRRRRRRRRRRRRRRWWWWWWWWWWWWWWWWWWWWW....
RRRRRRRRRRRRRRRRRRRRRRRRRWWWWWWWWWWWWWWWWWWWWW....
...
.CCCCCCCCCCCCCCC..................................
...

== ТАБЛИЦА: запрошено / фактически / отклонение ==

id        | type     | доля (%) | цель (клеток) | факт (клеток) | отклонение | статус
--------- | -------- | -------- | ------------- | ------------- | ---------- | ------
corridor1 | CORRIDOR | 10       | 250           | 225           | -25 (-10%) | ок
room1     | ROOM1    | 26       | 650           | 650           | 0          | ок
room2     | ROOM2    | 15       | 375           | 375           | 0          | ок

== ПРЕДУПРЕЖДЕНИЯ ==

нет
```

### 1.2 Символы карты

| Символ | Смысл (см. `render_grid`) |
|---|---|
| `*` | заблокированная клетка (blocked) |
| `.` | свободная клетка |
| `?` | неизвестный instance/тип (защита от повреждённого результата) |
| любой другой один символ | клетка кластера; символ = `ClusterType.symbol` из реестра спеки |

Факты о символах (из `space_manager/spec_io.py`, валидация `types`):

- символ — **ровно 1 код-поинт** (`len(symbol) != 1` отклоняется);
- символ **уникален** в реестре типов;
- символ может быть любым допустимым (включая кириллицу/Unicode) — кроме этого,
  `spec_io` НЕ запрещает `*`, `.`, `?` (известный риск upstream — §7 п.4).

### 1.3 Что отчёт НЕ содержит

- **Явных размеров W×H** — определяются из карты: `W = длина строки`, `H = число строк`;
- **Соответствия «символ → type_id»** — карта рисует символы, таблица выводит type_id;
  связь восстанавливается эвристикой (§6);
- id кластера в клетках карты — две клетки одного кластера и двух кластеров одного типа
  неотличимы по символам (docs/06 §3, замечание).

### 1.4 Блок невозможности размещения

При `feasible=False` в начало файла добавляется блок (`infeasible_block`, report.py):

```
НЕ УДАЛОСЬ РАЗМЕСТИТЬ ВСЕ КЛАСТЕРЫ.
Причина: <текст причины (может быть многострочным)>
Рассмотрите: уменьшение доли, смену shape на free, или расширение области.
```

Парсер фиксирует его дословно (`infeasibleText`) и флаг `infeasible = true`; UI показывает
красный баннер (04 §9). Карта/таблица при этом парсятся как обычно — частично размещённые
кластеры видны в 3D.

## 2. Семантическая модель: «комната»

**Решение (зафиксировано заказчиком):** комната = **связный компонент одинаковых
символов по 4-связности** (ортогональные соседи; диагонали НЕ считаются соединением).
Символы `*` и `.` комнатами НЕ являются. Символ `?` образует **псевдкомнаты** (4-связные компоненты, автоимена `unknown-{k}`, typeId = null, серый цвет) — см. §3, §6.4, кейс P10; псевдотип никогда не сопоставляется со строками таблицы.

Почему 4, а не 8: геометрия стен в viewer3d строится на ортогональном контуре клеток —
4-связные полиомино всегда имеют замкнутый ортогональный периметр без самосечений;
8-связные компоненты с «диагональными мостами» дают неориентуемые контуры (зазоры/
пересечения стен). Последствие для 8-связных кластеров солвера — ограничение v1,
задокументировано в §7 п.1.

Два кластера **одного типа**, соприкасающихся по ребру, на карте неотличимы → визуально
сливаются в одну комнату (docs/06 §3; ограничение v1, §7 п.2).

## 3. Модель данных парсера (TypeScript)

```ts
/** Один код-поинт карты: '.', '*', '?' или символ типа. */
type CellChar = string; // длина ровно 1 (Array.from-семантика)

interface Room {
  index: number;            // порядковый номер, 1-based, в порядке растрового обхода
  label: string;            // метка: id из таблицы (эвристика §6) либо автоимя §6.4
  symbol: CellChar;         // символ карты ('?' допустим — псевдотип «неизвестный»)
  typeId: string | null;    // type_id строки таблицы, если сопоставлена; иначе null
  tableRow: TableRow | null;// строка таблицы, если сопоставлена (для InfoPanel)
  cells: Array<[number, number]>;   // координаты клеток [x, y]
  size: number;             // = cells.length
  bbox: { x0: number; y0: number; x1: number; y1: number }; // включительные, по клеткам
  centroid: { x: number; y: number };  // среднее центров клеток (в координатах «угол клетки + 0.5»)
}

interface TableRow {
  id: string;               // колонка 'id'
  typeId: string;           // колонка 'type' (= type_id из реестра)
  share: number | null;     // 'доля (%)'; '—' → null (preset)
  target: number;           // 'цель (клеток)'
  actual: number;           // 'факт (клеток)'
  deviation: string;        // 'отклонение' — дословно ('0', '+1 (+3%)', ...)
  status: string;           // 'статус' — дословно ('ок' | 'недостача' | 'превышение')
}

type IssueLevel = 'error' | 'warning';
interface ParseIssue { code: string; level: IssueLevel; message: string; }

interface ParsedReport {
  width: number;            // W — из карты
  height: number;           // H — из карты
  map: CellChar[][];        // map[y][x], y = строка отчёта (сверху вниз)
  rooms: Room[];            // порядок — растровый обход (§4 шаг 5)
  blockedCells: Array<[number, number]>;
  unknownCells: Array<[number, number]>;   // клетки '?'
  tableRows: TableRow[];    // все корректно разобранные строки таблицы
  unmatchedRows: TableRow[];// строки, не сопоставленные ни с одной комнатой (§6.5)
  infeasible: boolean;      // присутствовал блок «НЕ УДАЛОСЬ…» (§1.4)
  infeasibleText: string | null;          // текст блока дословно
  warningsSection: string[];              // строки секции ПРЕДУПРЕЖДЕНИЯ (без 'нет')
  issues: ParseIssue[];       // все V-*/W-* по файлу (§5)
}

/** Бросается при ошибках уровня error (§5); .issues — собранные до сброса. */
class ReportParseError extends Error { constructor(public issues: ParseIssue[]) {} }
```

API парсера (чистая функция, без DOM/React):

```ts
function parseReport(text: string): ParsedReport; // бросает ReportParseError при V-*
```

## 4. Алгоритм парсинга

Сложность O(W·H). Все строковые операции — в семантике код-поинтов (`Array.from`),
чтобы совпасть с Python-рендером (символ = 1 код-поинт, §1.2).

```
parseReport(text):
  lines = text.split(/\r?\n/)                    # нормализация CRLF/LF
  issues = []

  # --- шаг 1. заголовок карты ------------------------------------------------
  i0 = index of line == "== КАРТА ==" (строгое равенство)
  if not found → ERROR V-NO-MAP

  # --- шаг 2. блок невозможности ---------------------------------------------
  firstNonEmpty = первая непустая строка файла
  infeasible = firstNonEmpty startsWith "НЕ УДАЛОСЬ"
  infeasibleText = (если infeasible) все строки от firstNonEmpty до строки перед i0, склеенные "\n"

  # --- шаг 3. извлечение карты -------------------------------------------------
  j = i0 + 1; while lines[j] == "" : j++         # пропуск пустой разделительной строки
  k = j
  while k < len(lines) and lines[k] != "" and
        lines[k] not in {"== ТАБЛИЦА: запрошено / фактически / отклонение ==", "== ПРЕДУПРЕЖДЕНИЯ =="}:
      mapLines.append(lines[k]); k++
  if mapLines empty → ERROR V-MAP-EMPTY
  H = len(mapLines); W = codepoint_length(mapLines[0])
  for idx, line in mapLines:                     # валидация прямоугольности и символов
      L = codepoint_length(line)
      if L != W → ERROR V-MAP-RECT (номер строки карты idx+1, ожидаемо W, получено L)
      for col, ch in enumerate(Array.from(line), 1):
          cp = codepoint(ch)
          if cp < 0x20 or cp == 0x7F → ERROR V-MAP-CHAR (строка idx+1, колонка col, U+%04X)
  if W > 200 or H > 200 → ERROR V-MAP-DIMS-LIMIT (W×H, лимит v1 = 200×200)
  map[y][x] = Array.from(mapLines[y])[x]

  # --- шаг 4. комнаты: BFS по 4-связности одинаковых символов -------------------
  visited[H][W] = false
  rooms = []; n = 0
  for y in 0..H-1, x in 0..W-1 (растровый обход):
      ch = map[y][x]
      if ch in {".", "*", "?"} or visited[y][x]: continue
      n += 1; cells = BFS((x,y), соседи: (x±1,y),(x,y±1); условие: в пределах, тот же ch)
      rooms.append(Room{ index: n, symbol: ch, cells, size: len(cells),
                         bbox/centroid из cells, label/typeId/tableRow — на шаге 6 })
  if n > 128 → ERROR V-ROOMS-LIMIT (n, лимит v1 = 128)

  # --- шаг 5. служебные наборы ---------------------------------------------------
  blockedCells = [(x,y) where map[y][x] == "*"]
  unknownCells = [(x,y) where map[y][x] == "?"]
  if len(unknownCells) > 0 → WARN W-UNKNOWN-CELLS (число, первые ≤5 координат «(x,y), ...»)

  # --- шаг 6. таблица + эвристика меток -------------------------------------------
  tableRows = parseTableSection(lines, i0)       # §4.1; ошибки строк → WARN W-TABLE-ROW
  assignLabels(rooms, tableRows)                 # §6; unmatchedRows — побочный результат

  # --- шаг 7. предупреждения -------------------------------------------------------
  warningsSection = строки после заголовка "== ПРЕДУПРЕЖДЕНИЯ ==" до конца файла,
                    отбрасывая пустые и единственное "нет"

  if issues содержит level=error → throw ReportParseError(issues)
  return ParsedReport{...}
```

### 4.1 Разбор секции ТАБЛИЦА

```
i1 = index of line == "== ТАБЛИЦА: запрошено / фактически / отклонение ==" (строгое равенство)
if not found → WARN W-TABLE-MISSING; tableRows = []
for line в строках после i1 до следующего заголовка секции ("== ПРЕДУПРЕЖДЕНИЯ ==") или конца файла:
    if line == "" : continue
    if line startsWith "id " or set(line) ⊆ {"-"," ","|"} : continue      # шапка и разделитель
    parts = line.split(" | ")
    if len(parts) != 7 → WARN W-TABLE-ROW (номер строки в файле); continue
    id, typeId, share, target, actual, deviation, status = parts
    if not isInt(target) or not isInt(actual) → WARN W-TABLE-ROW; continue
    tableRows.append(TableRow{ id, typeId,
        share: (share == "—") ? null : parseFloat(share),
        target: int(target), actual: int(actual), deviation, status })
```

Ограничение формата: значения колонок не содержат ` | ` (id/typeId — идентификаторы,
остальные — числа/служебные слова) — предположение зафиксировано; строка с другим числом
полей → W-TABLE-ROW и пропуск (парсер деградирует мягко: метки станут автоименами).

## 5. Коды ошибок (V-*) и предупреждений (W-*)

### 5.1 Ошибки (уровень error — файл отклоняется, сцена не строится)

| Код | Условие | Текст сообщения (шаблон, RU) |
|---|---|---|
| `V-NO-MAP` | нет строки `== КАРТА ==` | «Файл не похож на отчёт space_manager: не найдена секция "== КАРТА =="» |
| `V-MAP-EMPTY` | после заголовка карты нет ни одной строки сетки | «Секция "== КАРТА ==" пуста» |
| `V-MAP-RECT` | длина строки ≠ W первой строки | «Карты не прямоугольная: строка {row} имеет длину {L}, ожидаемо {W}» |
| `V-MAP-CHAR` | управляющий символ (CP < 0x20 или 0x7F) в клетке | «Запрещённый символ U+{code:04X} в клетке ({x},{y})» |
| `V-MAP-DIMS-LIMIT` | W > 200 или H > 200 | «Сетка {W}×{H} превышает лимит v1 (200×200)» |
| `V-ROOMS-LIMIT` | число комнат > 128 | «Найдено {n} комнат — превышен лимит v1 (128)» |

### 5.2 Предупреждения (уровень warning — сцена строится, баннер в UI)

| Код | Условие | Текст сообщения (шаблон, RU) |
|---|---|---|
| `W-UNKNOWN-CELLS` | есть клетки `?` | «{n} клеток с неизвестным типом («?»): {первые ≤5 координат}(… и ещё m) — показаны серым псевдотипом» |
| `W-TABLE-MISSING` | нет секции ТАБЛИЦА | «Секция "== ТАБЛИЦА: запрошено / фактически / отклонение ==" не найдена — метки комнат автоматические» |
| `W-TABLE-ROW` | строка таблицы не разобрана (≠7 полей или не целые target/actual) | «Пропущена строка таблицы №{fileLine}: не распознана структура колонок» |

Блок «НЕ УДАЛОСЬ…» — не W-код: выделенное поле `infeasible/infeasibleText` (§1.4),
отображается красным баннером (04 §9). Секция «ПРЕДУПРЕЖДЕНИЯ» отчёта показывается
как есть (по строкам), без переработки.

## 6. Эвристика меток комнат (сопоставление с таблицей)

Задача: компоненту карты (известны `symbol`, `size`) сопоставить строку таблицы
(известны `id`, `typeId`, `actual`), чтобы показать в UI «кто есть кто». Явного
«символ → type_id» в отчёте нет (§1.3), поэтому сопоставление — по **фактическому числу
клеток** с ограничениями уникальности. Алгоритм детерминирован (растровый порядок).

### 6.1 Вход/выход

```
вход:  rooms[] (index, symbol, size) — растровый порядок; tableRows[] (id, typeId, actual) — порядок файла
выход: для каждой комнаты label + typeId/tableRow; unmatchedRows[]
```

### 6.2 Правила

1. Участвуют только строки с `actual > 0` (кластер не размещён → компонента нет).
2. Кандидаты комнаты C: строки R, у которых `R.actual == C.size`.
3. Каждая строка таблицы используется **не более чем для одной** комнаты.
4. Итеративное назначение однозначных совпадений: пока есть изменения — по комнатам в
   растровом порядке назначаем комнату единственному свободному кандидату.
5. Оставшиеся (0 или ≥2 кандидатов) — без назначения; их метки — автоимена (6.4),
   строки-кандидаты уходят в `unmatchedRows`.
6. При равных условиях приоритет — комнате, **ранее встретившейся в растровом обходе**
   (следствие порядка итерации 4; правило зафиксировано для воспроизводимости).

Псевдокод:

```
used = {}                      # id строки → комната
progress = true
while progress:
    progress = false
    for C in rooms (растровый порядок):
        if C уже назначена: continue
        cands = [R for R in tableRows if R.actual > 0 and R.actual == C.size and R.id not in used]
        if len(cands) == 1:
            C.label = cands[0].id; C.tableRow = cands[0]; C.typeId = cands[0].typeId
            used[cands[0].id] = C; progress = true
unmatchedRows = [R for R in tableRows if R.id not in used]
# комнаты без назначения получают автоимена ниже
```

### 6.3 Типовые случаи

| Ситуация | Результат |
|---|---|
| 1 комната символа `R` (650 кл.), в таблице строка `room1` с факт=650 | `label = "room1"`, `typeId = "ROOM1"` |
| 2 комнаты `R`: 375 и 225; строки `a`(375), `b`(225) | каждая получает свою строку (уникальные размеры) |
| 2 комнаты `R`: обе по 300; одна строка `x`(300) | ранняя в обходе → `label="x"`, поздняя → автоимя; `x` не дублируется |
| 1 комната `R` (300); две строки `x`(300), `y`(300) | однозначного нет → автоимя; `x`,`y` в unmatchedRows |
| строка с факт=0 (не размещён, infeasible-отчёт) | всегда в unmatchedRows (UI: «(не размещён)») |

### 6.4 Автоимена

Для комнаты без сопоставления: `label = "room-{SYMBOL}-{k}"`, где `SYMBOL` — символ карты
в верхнем регистре, `k` — счётчик **по символу** в растровом порядке (1-based). Примеры:
`room-R-1`, `room-R-2`, `room-W-1`. Для символа `?`: `label = "unknown-{k}"`
(счётчик по `?`). Тип в UI для таких комнат — «—» (не определён по отчёту).

## 7. Ограничения и неоднозначности v1 (задокументированы, не баги)

1. **8-связный кластер может разделиться** на несколько комнат: солвер строит кластеры
   по 8-окрестности (docs/03 §rules), а комнаты — по 4-связности (§2). Тонкий «зигзаг»,
   связанный диагоналями, покажется двумя помещениями. Принято для v1 (причина — п. §2);
   в roadmap v2 — режим 8-связности со спецобработкой контура.
2. **Слияние кластеров одного типа**: соприкасающиеся по ребру кластеры одного типа
   неотличимы на карте → одна комната (docs/06 §3). Если в таблице для этого типа ≥2
   строки с суммой, равной размеру комнаты, — ни одна не сопоставится однозначно
   (§6.3, случай 4), метка автоматическая.
3. **unmatchedRows ≠ ошибка**: строка таблицы может остаться без комнаты при любых
   неоднозначностях §6.3; она показывается в списке комнат отдельным блоком «в таблице,
   но не найдена на карте» (04 §5).
4. **Риск символов-резервов upstream**: `spec_io` не запрещает типам символы `*`, `.`,
   `?`; если спека использовала такой символ, клетки этого типа viewer3d интерпретирует
   как blocked/free/unknown соответственно. Детектировать по одному отчёту невозможно —
   ограничение формата (в roadmap v2 — машинночитаемый файл размещения).
5. **Отсутствуют в отчёте**: имена типов (`name` из реестра), правила, seed — viewer3d
   их не показывает; тип комнаты известен только как type_id из таблицы (когда сопоставлен).

## 8. Палитра цветов символов (модуль `palette.ts`)

**Решение:** фиксированная палитра из 16 различимых цветов; назначение — по порядку
первого появления символа в растровом обходе карты (детерминировано). Символ `?`
выделен цветом вне палитры: `#808080`.

```ts
export const PALETTE: string[] = [
  '#4e79a7', '#f28e2b', '#59a14f', '#e15759', '#76b7b2', '#edc948',
  '#af7aa1', '#ff9da7', '#9c755f', '#b07aa1' /* ... до 16 цветов, см. реализацию */
];
export function symbolPalette(map: CellChar[][]): Map<string, string>; // symbol → hex
```

Требования к палитре: контраст между соседними по порядку цветами; читаемость на белом
фоне (полы) и на серых стенах; при > 15 символах цвета зацикливаются (допустимо —
лимит комнат 128 не гарантирует уникальность цветов).

Стена, базовая плита и фон — фиксированные цвета: стена `#e0e0e0` (прозрачность —
параметр), плита под сеткой `#c9ced3`, фон сцены `#f2f4f7`, blocked-блоки `#444444`
(таблица в [03](./03-wall-geometry.md) §9).
