# 03. Геометрия стен и модель 3D-сцены

> Сводный индекс: [README.md](./README.md) · Парсер/модель комнаты: [02-input-parser](./02-input-parser.md) §2–§3 ·
> UI-параметры: [04-ui-interaction](./04-ui-interaction.md) §3 · Тесты геометрии: [05-testing-acceptance](./05-testing-acceptance.md) §3

Документ описывает **ядро модуля `viewer3d/src/lib/walls.ts`** (чистые TS-функции,
без three.js/DOM — полностью unit-тестируемы) и правила построения остальных
объёмов сцены (полы, blocked, базовая плита).

## 1. Системы координат

**Сетка.** Клетки `(x, y)`, `x ∈ [0..W)`, `y ∈ [0..H)`; строки карты отчёта — по Y
сверху вниз (y=0 — верхняя строка). Углы клеток образуют целочисленную решётку
точек `(gx, gy)`, `gx ∈ [0..W]`, `gy ∈ [0..H]`.

**Мир (three.js).** Плоскость плана — XZ; ось Y — вверх. Центр сетки — начало координат:

```
точка решётки (gx, gy)  →  X = (gx − W/2) · S ,   Z = (gy − H/2) · S
```

Где `S` — масштаб «мировых единиц на клетку» (параметр UI, дефолт 1; README §3 п.3).
Все геометрические функции считают в мировых единицах; промежуточные алгоритмы
(рёбра, сегменты) — в единицах сетки, пересчёт ×S — один раз при выгрузке боксов.

**Высоты (мировые единицы):**

| Объект | Y-диапазон |
|---|---|
| базовая плита под сеткой | `−0.25 … 0` (толщина 0.25 — константа, не параметр) |
| полы комнат (плоскости из клеток) | `y = +FLOOR_EPS`, где `FLOOR_EPS = 0.02 · S` (избегает z-fighting с плитой) |
| стены (боксы) | `0 … Hw` |
| blocked-блоки | `0 … Hw` (та же высота, что у стен — вводная №2) |

## 2. Модель комнаты (ввод из парсера)

Комната = полиомино: множество клеток `cells ⊂ [0..W)×[0..H)` (4-связный компонент
одного символа, [02](./02-input-parser.md) §2). Для каждой комнаты парсер считает:
`size`, `bbox {x0,y0,x1,y1}` (включительные), `centroid = среднее центров клеток`
(центр клетки `(x,y)` — точка `(x+0.5, y+0.5)` решётки). Пример:

```
комната A:              bbox: x0=0,y0=0,x1=1,y1=1; size=3
    +---+---+           centroid: среднее (0.5,0.5),(1.5,0.5),(0.5,1.5) = (0.833, 0.833)
    | A | A |
    +---+---+
    | A | . |
    +---+---+
```

## 3. Граничные рёбра: извлечение

**Определения.** Единица границы — ортогональное ребро длиной 1 клетка на решётке
углов:

- `h(x, y)` — горизонтальное ребро на линии `gy = y`, от `gx = x` до `gx = x+1`;
  разделяет клетки `(x, y−1)` (сверху) и `(x, y)` (снизу);
- `v(x, y)` — вертикальное ребро на линии `gx = x`, от `gy = y` до `gy = y+1`;
  разделяет клетки `(x−1, y)` (слева) и `(x, y)` (справа).

**Правило извлечения.** Для каждой клетки `c = (x,y)`, чей символ — символ комнаты
(не `.`, `*`, `?`), и для каждого из 4 направлений: если сосед **вне сетки ИЛИ его
символ ≠ символу c**, то сторона клетки в этом направлении входит в множество
границы. Соответствие «сторона → ребро» для клетки `(x,y)`:

| Сторона (направление соседа) | Ребро |
|---|---|
| верх (`(x, y−1)`) | `h(x, y)` |
| низ (`(x, y+1)`) | `h(x, y+1)` |
| лево (`(x−1, y)`) | `v(x, y)` |
| право (`(x+1, y)`) | `v(x+1, y)` |

**Решение (дедупликация):** множество границ считается **глобально** — как объединение
по всем комнатам с дедупликацией по ключу ребра. Общее ребро двух соседних комнат
(например, коридор между двумя стенами) встречается дважды — по одному разу от каждой
стороны; на него ставится **одна** стена (один бокс). Последствия: (а) нет z-fighting
от двух совпадающих боксов; (б) каждая комната остаётся замкнутой, т.к. её полный
периметр (включая границы со свободными `.` и blocked `*` клетками — вводная №2 ТЗ)
входит в объединение.

Псевдокод:

```
boundaryEdges(map):
    E = set()                       # ключи ("h",x,y) / ("v",x,y)
    for y in 0..H-1, x in 0..W-1:
        ch = map[y][x]
        if ch in {".","*","?"}: continue
        if out(ch, x,   y-1): E.add("h", x, y)      # верх
        if out(ch, x,   y+1): E.add("h", x, y+1)    # низ
        if out(ch, x-1, y  ): E.add("v", x, y)      # лево
        if out(ch, x+1, y  ): E.add("v", x+1, y)    # право
    return E
# out(ch, nx, ny) := (nx,ny вне [0..W)×[0..H)) ИЛИ map[ny][nx] != ch
```

## 4. Склейка коллинеарных рёбер в сегменты

Рёбра группируются по линии и склеиваются в **максимальные прямолинейные прогоны**:

```
mergeSegments(E):
    hRuns = для каждого y: отсортированные по x рёбра h(x,y) →
            consecutive-склейка: если next.x == prevEndX, продлеваем (len += 1)
            результат: {axis:'h', x0, y, len}   # покрывает gx ∈ [x0, x0+len]
    vRuns = аналогично по x: {axis:'v', x, y0, len}   # покрывает gy ∈ [y0, y0+len]
```

Склейка проходит **сквозь** T-пересечения (прогон не прерывается, если в промежуточной
точке к нему примыкает перпендикулярное ребро) — см. эталонный пример §6 (прогон
`h(0,3,len=4)` склеен из рёбер двух разных комнат).

## 5. Угловые стыки: правило продолжения на T/2

### 5.1 Проблема: зазор во внешнем углу

Два бокса толщиной `T`, встречающиеся под 90° в точке решётки `P` (боксы центрированы
на линиях рёбер), не перекрывают квадрат `T/2 × T/2` во **внешнем** углу:

```
План (X →, Y/Z вниз). P — точка стыка. A — горизонтальный бокс, кончается в P;
B — вертикальный бокс, идёт от P вниз. Боксы центрированы на линиях рёбер.

   ┌───────────────┬───────────┐
   │      A        │   QNE ✗   │  ← QNE: x∈[px, px+T/2], z∈[py−T/2, py] — НЕ покрыт
   ├───────────────┼───────────┤  линия z = py (ось A)
   │      A        │     B     │
   └───────────────┴───────────┘
                    B: x∈[px−T/2, px+T/2], z ≥ py

Покрытие окрестности P четырьмя квадратами T/2×T/2:
   A покрывает QNW и QSW (вся полоса |z−py|≤T/2 при x≤px),
   B покрывает QSW и QSE (вся полоса |x−px|≤T/2 при z≥py)  →  QNE остаётся дыркой.
```

### 5.2 Правило продолжения

**Решение:** конец прямолинейного прогона **продолжается на `T/2`** (мировых единиц,
т.е. ровно на половину толщины) за конечную точку **если и только если** в этой точке
через неё проходит перпендикулярный сегмент:

- для конца `(px, py)` горизонтального прогона: существует вертикальный сегмент с
  `x == px` и `py ∈ [y0, y0+len]` (включительно);
- для конца `(px, py)` вертикального прогона: существует горизонтальный сегмент с
  `y == py` и `px ∈ [x0, x0+len]` (включительно).

Оба конца прогона проверяются независимо; продолжение может быть с одного конца, с
обоих или ни с одного.

Почему правило корректно во всех случаях:

| Конфигурация в точке P | Эффект продолжения |
|---|---|
| L-угол (два прогона заканчиваются в P) | закрывает зазор QNE (§5.1); оба прогона могут быть продолжены — их боксы перекрываются в углу, контур объединения остаётся чистым квадратом (пересечение скрыто внутри стены) |
| T-пересечение (один прогон проходит через P, второй заканчивается) | конец «пробки» продолжается в сторону, где нет полосы проходящего бокса → закрывает его зазор; с другой стороны продолжение целиком утончается в тело проходящего бокса (невидимо) |
| Свободный конец (перпендикуляра нет) | без продолжения — торец стены плоский, зазора нет по построению |

**Инвариант для реальных данных:** граница каждой комнаты — замкнутый ортогональный
контур; конец любого склеенного прогона является вершиной какого-то контура, а в
вершине контура всегда есть перпендикулярное ребро. Следовательно, для карт из
4-связных полиомино продолжение фактически применяется к обоим концам каждого прогона;
условная проверка оставляется ради робастности (дегенерированные/будущие режимы).

Реализация: строятся индексы `hSpansByY: Map<y, Array<[x0,x1]>>` и `vSpansByX:
Map<x, Array<[y0,y1]>>`; проверка «перпендикуляр через точку» — поиск span'а по линии
+ включительное сравнение (списки короткие; при желании — бинарный поиск).

## 6. Выгрузка боксов стен

```ts
interface WallBox { x: number; z: number; sx: number; sz: number; } // центр + размеры, XZ-плоскость, мировые единицы
interface WallParams { scale: number; wallThickness: number; }      // S и T (04 §3)

function buildWallBoxes(map: CellChar[][], p: WallParams): WallBox[];
// = boundaryEdges → mergeSegments → продолжения (§5.2) → формулы ниже
```

Для горизонтального прогона `{x0, y, len}` с продолжениями `e0` (конец у `gx=x0`) и
`e1` (конец у `gx=x0+len`):

```
sx = len·S + e0 + e1
sz = T
x  = (x0 + len/2 − W/2)·S + (e1 − e0)/2
z  = (y − H/2)·S
```

Для вертикального прогона `{x, y0, len}` с `e0` (конец у `gy=y0`) и `e1` (конец у
`gy=y0+len`):

```
sz = len·S + e0 + e1
sx = T
z  = (y0 + len/2 − H/2)·S + (e1 − e0)/2
x  = (x − W/2)·S
```

Сцена строит из каждого `WallBox` бокс three.js размера `(sx, Hw, sz)` с центром
`(x, Hw/2, z)`; `Hw` (высота) в чистую функцию **не передаётся** — меняется без
пересчёта XZ-геометрии.

### 6.1 Эталонный пример (используется в unit-тестах, 05 §3)

Сетка 4×3 (`W=4, H=3`), комнаты A/B/C/D и одна свободная клетка `(1,1)`:

```
     x=0 1 2 3
y=0 [ A A B B ]
y=1 [ A . C C ]
y=2 [ D D C C ]
```

Шаг 1 — рёбра: всего извлечено 28 (по сторонам всех клеток комнат); общих между
комнатами 5 (`v(2,0)`: A|B; `h(2,1)` и `h(3,1)`: B|C; `h(0,2)`: A|D; `v(2,2)`: C|D) →
**уникальных рёбер: 23**.

Шаг 2 — склейка в прогон (8 сегментов):

| # | Прогон | Покрывает | Источник рёбер |
|---|---|---|---|
| H1 | `h: x0=0, y=0, len=4` | верхний периметр A+B | 4 ребра |
| H2 | `h: x0=1, y=1, len=3` | низ A над свободной `(1,1)` + граница B\|C — consecutive-склейка в один прогон (§4) | A; B, C (общие) |
| H4 | `h: x0=0, y=2, len=2` | граница A|D (`h(0,2)`) + верх D над свободной клеткой `(1,1)` (`h(1,2)`) | 2 ребра |
| H5 | `h: x0=0, y=3, len=4` | нижний периметр D+C (склейка **сквозь** T-стык с V2) | 4 ребра двух комнат |
| V1 | `v: x=0, y0=0, len=3` | левый периметр (A сверху, D снизу) | 3 ребра |
| V2 | `v: x=1, y0=1, len=1` | вертикаль между клеткой `(0,1)` комнаты A и свободной клеткой `(1,1)` | 1 ребро (A) |
| V3 | `v: x=2, y0=0, len=3` | граница A/B → C (над `.`) → C/D — одна непрерывная стена | 3 ребра трёх пар |
| V4 | `v: x=4, y0=0, len=3` | правый периметр (B сверху, C снизу) | 3 ребра |

Шаг 3 — боксы. Параметры эталона: `S = 1`, `T = 0.5` → продолжение `e = T/2 = 0.25`.
По инварианту §5.2 оба конца каждого прогона имеют перпендикуляр → везде `e0 = e1 = 0.25`.

| # | Бокс (x, z, sx, sz) | Проверка |
|---|---|---|
| H1 | `(0, −1.5, 4.5, 0.5)` | x: (0+2−2)·1+(0.25−0.25)/2 = 0; z: (0−1.5)·1 = −1.5; sx: 4+0.5 |
| H2 | `(0.5, −0.5, 3.5, 0.5)` | x: (1+1.5−2) = 0.5; sx: 3+0.5 |
| H4 | `(−1, 0.5, 2.5, 0.5)` | z: (2−1.5) = 0.5 |
| H5 | `(0, 1.5, 4.5, 0.5)` | z: (3−1.5) = 1.5 |
| V1 | `(−2, 0, 0.5, 3.5)` | x: (0−2) = −2; z: (0+1.5−1.5) = 0 |
| V2 | `(−1, 0, 0.5, 1.5)` | x: (1−2) = −1; sz: 1+0.5 |
| V3 | `(0, 0, 0.5, 3.5)` | x: (2−2) = 0 |
| V4 | `(2, 0, 0.5, 3.5)` | x: (4−2) = 2 |

Ожидаемый результат функции для этого примера — **ровно эти 8 боксов** (множество;
порядок в реализации фиксирован: сначала h-прогоны по y,x, затем v-прогоны по x,y0).
Пересечения (например, H2×V3) — ожидаемы и допустимы (§5.2).

Схема результата (вид сверху; `█` — тело стены толщиной 0.5, точка сетки = линия рёбер):

```
   x: -2      -1       0       1       2
y=-1.5   ███████████████████████          ← H1 (продолжена на 0.25 за углы)
         █              █
y=-0.5   █     ████████  █    █            ← V1 | H2 (сквозной) | V3, V4
         █     █  █  █   █    █
 y=0.5   █     ██  ████  █    █            ← V2, H4, V3
         █              █
y= 1.5   ███████████████████████           ← H5
```

## 7. Инвариант покрытия (автопроверка в тестах)

Для любой комнаты `R` и результата `buildWallBoxes`: каждое ребро границы `R` (§3,
без дедупликации по комнатам) должно пересекаться хотя бы с одним боксом стены —
точнее, каждый единичный сегмент `(x..x+1, y)` / `(x, y..y+1)` должен лежать в XZ-проекции
какого-то бокса (с точностью до `1e-9`). Проверка реализована как чистая функция
`assertBoundaryCovered(map, boxes)` и проходит для всех фикстур (05 §5). Это
автоматизированная гарантия «комната замкнута стенами» без визуальной приёмки.

## 8. Blocked-блоки

Для каждой клетки `*`: бокс размера `(S, Hw, S)` с центром
`(x + 0.5 − W/2)·S, (Hw/2), (y + 0.5 − H/2)·S` — т.е. блок занимает клетку целиком,
высотой вровень со стенами. Цвет `#444444` (тёмный, отличим от стен и полов).
Показываются при `params.showBlocked = true` (дефолт; тумблер — 04 §3). Рендер —
один InstancedMesh (число блоков ≤ W·H).

## 9. Полы, базовая плита, цвета

| Объект | Геометрия | Цвет/материал |
|---|---|---|
| пол комнаты | плоскость из единичных квадов её клеток (один mesh на комнату — для подсветки выделения) | цвет символа по палитре [02](./02-input-parser.md) §8; при выделении — emissive-подсветка (04 §7) |
| базовая плита | бокс `(W+8)·S × 0.25 × (H+8)·S`, верхняя грань `y = 0`, центр сетки | `#c9ced3` |
| фон сцены | — | `#f2f4f7` |
| стены | боксы §6, InstancedMesh | `#e0e0e0`, opacity = `params.wallsOpacity` (1 → непрозрачный материал; < 1 → transparent) |
| blocked | блоки §8 | `#444444` |

Освещение сцены: ambient `0.6` + directional из `(50, 100, 30)` интенсивность `0.8`
(фиксировано; не параметры UI). Материалы — Lambert (дешёвые; теней в v1 нет —
roadmap §8 ТЗ [05](./05-testing-acceptance.md)).

**Таблица параметров геометрии** (полная таблица с диапазонами и шагом — 04 §3):

| Параметр | Обозначение | Дефолт | Влияние |
|---|---|---|---|
| масштаб «ед. на клетку» | S | 1 | мировые размеры сетки, полов, блоков; пересчёт боксов стен ×S |
| высота стены | Hw | 3 | Y-размер боксов стен и блоков (без пересчёта XZ) |
| толщина стены | T | 0.25 | `sz`/`sx` боксов + продолжения §5.2; пересчёт `buildWallBoxes` |

## 10. Сложность и производительность

- Извлечение рёбер: O(W·H) (≤ 4 проверки на клетку); при 200×200 — ≤ 160k операций.
- Склейка: O(E log E) по сортировке; E ≤ 4·W·H.
- Проверки углов: O(число концов прогонов × длина списка span'ов линии) — в реальных
  картах пренебрежимо мала (индексы из §5.2).
- **Бюджет:** полный пересчёт `buildWallBoxes` при смене S/T на сетке 200×200 < 100 мс
  (фиксировано как NFR, замер — [05](./05-testing-acceptance.md) §7). Пересчёт
  триггерится debounce'ом 200 мс при перетаскивании слайдеров (04 §3 примечание).
