# 05. Тестирование и приёмка

> Сводный индекс: [README.md](./README.md) · Парсер/коды ошибок: [02-input-parser](./02-input-parser.md) §4–§6 ·
> Геометрия/эталон: [03-wall-geometry](./03-wall-geometry.md) §5–§7 · UI: [04-ui-interaction](./04-ui-interaction.md)

## 1. Политика тестирования

| Слой | Инструмент | Что покрывается |
|---|---|---|
| `lib/reportParser.ts`, `lib/walls.ts`, `lib/palette.ts` | **Vitest** (unit, node-среда, без DOM) | 100% кодов V-*/W-*; алгоритм меток (§6 ТЗ 02); эталонная геометрия стен (ТЗ 03 §6.1); инвариант покрытия (ТЗ 03 §7) |
| SPA в браузере | **Playwright** (e2e, Chromium headless) | загрузка файла → список комнат; параметры; PNG-снапшот; ошибка парсинга в UI |
| Визуальные аспекты 3D (WebGL) | ручной чек-лист (§6) | внешний вид стен/полов, плавность камеры — e2e WebGL-пиксели НЕ проверяет (решение: headless SwiftShader нестабилен для pixel-ассертов; e2e ограничивается DOM + наличием canvas) |
| Совместимость с реальным CLI | интеграционный тест (§5) | свежесгенерированный отчёт `spaec_manager` отображается корректно |

Скрипты npm — как в `editor/package.json`: `test` (vitest run), `e2e`
(`npm run build && playwright test`). e2e поднимает prod-сервер на порту **3210**
(`playwright.config.ts`, webServer: `tsx server/index.ts`, env PORT=3210).

## 3. Unit-тесты геометрии (`tests/unit/walls.test.ts`)

| # | Кейс | Ожидание |

| G6 | инвариант покрытия (ТЗ 03 §7): `assertBoundaryCovered` на G1, `report_basic.txt`, `report_minimal.txt` | true для всех |
| G7 | отрицательный: из результата G1 удалить бокс H2 → `assertBoundaryCovered` | false (инвариант чувствителен к пропавшей стене) |
| G8 | пустая карта (все `.`) | 0 боксов, без исключений |
| G9 | комната-полоса 1×N (N=7) в середине сетки | прогоны: 2 горизонтальных len=N + 2 вертикальных len=1; формулы боксов по ТЗ 03 §6 — сверить вручную |

## 5. Сквозной приёмочный тест (совместимость с CLI)

**Критический тест** (интеграционный, vitest):

1. если существует `.venv/bin/python` в корне репозитория — выполнить
   `python -m spaec_manager place examples/spec_basic.yaml --seed 7 --out <tmp>/fresh.txt`;
   иначе использовать закоммиченную фикстуру `report_basic.txt` (режим skip-с-пометкой,
   паттерн интеграционных тестов `editor/`);
2. `parseReport(fresh)` → без ошибок;
3. комнаты: sizes {650, 375, 225}, метки `room1`/`room2`/`corridor1`, типы
   ROOM1/ROOM2/CORRIDOR (значения зафиксированы проверкой 2026-09-13; при смене
   поведения солвера тест обновляется осознанно, а не «как получится»);
4. `assertBoundaryCovered(map, buildWallBoxes(map, {scale:1, wallThickness:0.25}))` → true.

Смысл: любой отчёт, который реально генерирует система размещения, viewer3d понимает и
окружает стены полностью.

## 6. Ручной чек-лист приёмки (визуальная часть)

Выполняется в браузере (Chrome), prod-сборка; отчёт — `report_basic.txt` (+ для п.9 —
infeasible-отчёт). Все пункты должны выполняться:

| # | Действие | Ожидание |
|---|---|---|
| 1 | Загрузить `report_basic.txt` | сцена построилась < 2 с; видны 3 цветных пола (R/W/C по палитре), стены серые, подписи комнат на полу |
| 2 | Вращение ЛКМ / зум колесом / панорама ПКМ | плавное, без «залипаний»; видно со всех сторон, включая низ/бок стен |
| 3 | Пресеты `1/2/3` (или кнопки) | изометрия → сверху → спереди; после «сверху» орбита не заедает (смещение 0.001·D работает) |
| 4 | Слайдер «Прозрачность стен» → 0.3 | стены полупрозрачные, полы видны сквозь них |
| 5 | «Скрыть стены» + пресет «сверху» | плоская цветная карта комнат — соответствует ASCII-карте отчёта (сравнить с блоком КАРТА) |
| 6 | «Показывать blocked» off/on | тёмные блоки появляются/скрываются; на `report_basic.txt` блокировок нет (blockedFile: null) — проверить на спеке с блокировкой, напр. генерации отчёта по спеке с `blockedFile` |
| 7 | Клик по полу комнаты room1 | пол подсвечен, строка в списке подсвечена, InfoPanel: 650 клеток, тип ROOM1, статус «ок» |
| 8 | Клик по строке `corridor1` в списке | камера перелетела к коридору (изометрический вид сфокусирован), комната подсвечена; `Esc` — выделение сброшено |
| 9 | Загрузить infeasible-отчёт (`report_infeasible.txt`) | красный баннер «НЕ УДАЛОСЬ…» с причиной; частично размещённые комнаты видны в 3D |
| 10 | «PNG» → открыть скачанный файл | валидный PNG, на нём сцена (без DOM-панелей) |
| 11 | Сменить масштаб 1→2 и высоту стены 3→8, затем «Сбросить параметры» | размеры изменились корректно; после сброса — дефолты таблицы 04 §3 |
| 12 | Производительность: загрузить отчёт по спеке 200×200 (см. ниже), orbit-вращение | ≥ 30 FPS (Chrome → Performance → запись вращение ~3 с); пересчёт при смене T < 100 мс (Network/Performance timeline) |

Генерация отчёта 200×200 для п.12: временная спекация `/tmp/spec_big.yaml`
(`grid: {width: 200, height: 200}`, `types: {A:{symbol:"a"},B:{symbol:"b"},C:{symbol:"c"},D:{symbol:"d"}}`,
4 кластера по 25% free) → `.venv/bin/python -m spaec_manager place /tmp/spec_big.yaml --seed 1`.
Допустим и частично размещённый результат — для замера важна сетка 200×200.

## 7. Нефункциональные требования (производительность, лимиты)

| Метрика | Требование | Способ проверки |
|---|---|---|
| Парсинг отчёта 200×200 | ≤ 50 мс | vitest-замер (fixture-генерация) в CI-запуске, порог в тесте |
| `buildWallBoxes` 200×200 | ≤ 100 мс | то же |
| Orbit при 200×200 | ≥ 30 FPS (десктоп, Chrome) | ручной чек-лист п.12 |

Среда: Node ≥ 20 (dev/build), браузеры — современные Chrome/Firefox/Safari (desktop);
CI-браузер e2e — Chromium.

## 8. Известные ограничения v1 и roadmap v2

**Ограничения v1 (приняты, задокументированы):**

1. проёмов/дверей в стенах нет; высота стен одна на все комнаты (вводная №2);
2. комнаты — по 4-связности: 8-связный «зигзаг» солвера может разделиться на две
   комнаты (ТЗ 02 §7 п.1);
3. кластеры одного типа, соприкасающиеся по ребру, сливаются в одну комнату; метки —
   эвристика (неоднозначные случаи → автоимена + блок «не найдено на карте», ТЗ 02 §6–§7);
4. стены не подсвечиваются при выделении комнаты (общие для соседей); подписи Html
   видны сквозь стены; теней нет;
5. тип комнаты известен только как type_id из таблицы (имена `name` реестра в отчёт не
   входят);
6. один отчёт за сессию; refresh = потеря (без beforeunload — данных для сохранения нет).

**Roadmap v2 (не блокирует v1):** проёмы/двери между примыкающими комнатами; различная
высота стен; машинночитаемый файл размещения (id кластера в каждой клетке — снимает
все символные неоднозначности); режим 8-связности; экспорт GLB/OBJ; анимации камеры и
теней; сравнение двух отчётов наложением.
