# 08. Правило работы: декомпозиция и субагенты (СТРОГО последовательно)

> Сводный индекс: [../README.md](../README.md) · План реализации: [07-implementation-plan.md](./07-implementation-plan.md)

Это **обязательное процессное правило** для всех сессий разработки проекта.
Оно фиксирует, КАК выполняется работа, и должно соблюдаться всегда.

## 1. Декомпозиция на подзадачи

Всю работу по разработке нужно **разбивать на подзадачи**. Каждая подзадача —
это хорошо ограниченный кусок с явным входом, выходом и критерием готовности
(напр. «модуль `rules.py` + unit-тесты», см. таблицу подзадач в [07](./07-implementation-plan.md) §2).

## 2. Делегирование исполнения субагентам

Исполнение каждой подзадачи **делегировать субагенту** (sub-agent), а не делать
всё напрямую «руками» в основной сессии. Субагент получает:
- точное описание подзадачи и её критерий готовности;
- ссылки на нужные документы из `docs/`;
- чёткое описание ожидаемого результата (какие файлы, какие тесты).

## 3. СТРОГО по очереди (последовательно) — КРИТИЧНО

Субагенты должны работать **строго по одному за раз**, последовательно:

- **Нельзя** запускать несколько субагентов параллельно.
- Оркестратор (основная сессия) **не должен продолжать свою работу параллельно
  с работающим субагентом**. Причина: LLM-сервер, на котором работает оркестратор,
  настроен на **однопоточную** работу (один поток запросов). Параллельная активность
  оркестратора и субагента приведёт к конфликтам/гонкам.

Правильный цикл:

```
1. Сформулировать подзадачу N с критерием готовности.
2. Запустить ОДИН субагент для подзадачи N.
3. ПОДОЖДАТЬ полного завершения субагента (не делать ничего параллельно).
4. Принять результат: проверить по критерию готовности / тестам.
5. При необходимости — дать следующий шаг тому же или новому субагенту.
6. Перейти к подзадаче N+1.
```

## 4. Чек-лист перед запуском субагента

- [ ] Подзадача разграничена (один модуль/шаг, а не «всё сразу»).
- [ ] Указаны входы, ожидаемый результат и критерий готовности.
- [ ] Приведены ссылки на релевантные `docs/*`.
- [ ] Сейчас **не запущен** другой субагент (последовательность соблюдена).

## 5. Запрещено

- Параллельный запуск нескольких субагентов.
- Продолжение оркестратором активной работы во время выполнения субагента.
- Делегирование «нечётких» подзадач без критерия готовности.
