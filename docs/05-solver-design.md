# 05. Проектирование солвера

> Сводный индекс: [../README.md](../README.md) · Правила: [04-rules-and-adjacency.md](./04-rules-and-adjacency.md)

Задача размещения — NP-hard в общем виде (родственная упаковке полиомино).
Для сеток разумного размера достаточно **backtracking + эвристики + обрезка**.
Ниже — целевая функция, алгоритм и механизмы диагностики.

## 1. Ввод/вывод солвера

- Вход: `PlacementSpec` → построенная `Grid` (с блокировками и preset) + список
  размещаемых экземпляров (все, кроме уже занятых preset).
- Выход: `PlacementResult` — либо валидное размещение (+ предупреждения о
  мягких отклонениях), либо `feasible=False` с причиной.

## 2. Целевая функция (мягкая)

База процентов: `F = число клеток, не заблокированных` (см. [02](./02-domain-model.md) §8).
Цель экземпляра: `n_i = round(F * area_percent_i / 100)`.

Солвер минимизирует отклонение фактических площадей от целей, сохраняя пропорции:

```
cost = Σ_i |actual_i − n_i|                      # базовая метрика (L1 по кластерам)
     + λ * Σ_i (1 − fill_ratio_i)                # штраф за невыпуклость (soft)
```

- Увеличение площади в большую сторону допустимо; «лишнее» при `fillAll: true`
  распределяется пропорционально долям.
- Недостача допустима, но каждая существенная недостача → предупреждение в отчёте.
- Приоритет: сначала **осуществимость** (все кластеры стоят и все жёсткие условия
  соблюдены), затем — минимизация `cost`.

## 3. Жёсткие ограничения (нарушение = откат ветки поиска)

1. Кластер связен по 8-окрестности (один экземпляр — одна связная область).
2. Форма соблюдена, если задана (`rectangle` / `circle`).
3. Ячейки кластера не в блокировках и не в preset.
4. Соседство: ни одна пара граничащих ячеек из *разных* экземпляров не входит в
   `forbidden` (и соблюдён whitelist `allow`, если задан). Однотипные — всегда ок.
5. Соблюдены жёсткие `size.min/max`, если заданы.

## 4. Валидаторы и оценщики (чистые функции)

- `is_connected(cells, connectivity=8) -> bool`
- `is_rectangle(cells) -> bool` — клетки = весь bounding-box, bbox заполнен.
- `is_circle(cells, tol) -> bool` — существует центр/радиус, покрытие в пределах допустимости.
- `fill_ratio(cells) -> float` — площадь / площадь bbox (метрика выпуклости).
- `adjacency_ok(cell_a_type, cell_b_type, rules) -> bool` — правило §2 из [04](./04-rules-and-adjacency.md).

## 5. Алгоритм поиска

**Backtracking + MRV + forward-checking:**

1. **Упорядочение (MRV).** Сначала размещаем «самый жёсткий» кластер:
   - сначала с заданной формой (`rectangle`/`circle`) — меньше вариантов;
   - затем с бо́льшей целевой площадью / более ограниченным соседством.
2. **Генерация кандидатов.** Для текущего кластера генерируем связные области
   нужного (приблизительного) размера на свободных клетках:
   - отфильтрованные формой (если задана);
   - с учётом того, что после постановки не нарушаются `forbidden`-пары
     с уже поставленными соседями и с границами области;
   - отсортированные по `fill_ratio` (предпочтительнее выпуклые).
3. **Постановка + forward-checking.** Ставим кандидата, затем проверяем
   осуществимость остатка:
   - хватает ли оставшейся свободной площади на сумму целей остальных кластеров;
   - содержит ли свободная область связные фрагменты достаточного размера для
     каждого оставшегося кластера (иначе — тупик, откат);
   - не «заперты» ли какие-то клетки так, что их нельзя использовать.
4. **Рекурсия.** Переходим к следующему кластеру. Если дошли до конца — получили
   валидное размещение; считаем `cost` и храним лучшее.
5. **Остановка.** Достаточно **одного** размещения (см. [01](./01-problem-statement.md) §7).
   Но чтобы результат был «как можно ближе» к долям, поиск ведётся с бюджетом:
   ограничением по времени/числу узлов и удержанием лучшего найденного `cost`.

## 6. Уточнения, которые фиксируем при кодировании

- Влияние preset на базу F и целевые площади (по умолчанию база = «не блокировки»,
  preset — жёсткое ограничение «не перекрывать»).
- Точная метрика/допуск `is_circle`.
- Порог «существенной недостачи» для предупреждения (напр. отклонение > 10% цели).
- Бюджет поиска (дефолт времени/итераций) и его настройка из CLI.

## 7. Диагностика невозможности размещения

При `feasible=False` солвер должен назвать **конкретную причину** (не просто «нет»):
- не хватает свободной площади под сумму целей;
- нет связного фрагмента нужного размера/формы для кластера X;
- правило соседства `forbidden` делает размещение невозможным (какие типы конфликтуют);
- заданная форма (rect/circle) не вписывается на оставшейся области.

Для этого при обрыве ветки поиска запоминаем тип конфликта и его частоту; в отчёте
выводим наиболее частую/последнюю причину.

## 8. Масштабирование (на будущее)

Если сетки станут крупными и backtracking упрётся — переход к **SAT-энкодингу**
(тип ячейки = переменная, связность через flow-based формулировку). Архитектура
солвера изолирована в отдельном модуле, чтобы подменить стратегию без изменения
модели и отчёта.
