# 06. Ввод, вывод и отчётность

> Сводный индекс: [../README.md](../README.md) · Формат входа: [03-placement-spec.md](./03-placement-spec.md)

## 1. Вход (файлы)

| Файл | Обязательность | Назначение |
|---|---|---|
| спекация `.yaml` | да | размеры сетки, типы, правила, список кластеров |
| `blockedFile` (текст) | опц. | маска блокировок (`*`), размер = `grid` |
| `presetFile` (текст) | опц. | предзаполненная карта неподвижных кластеров, размер = `grid` |

## 2. CLI (черновик)

```bash
# базовый вызов: отчёт выводится в stdout и сохраняется в result-<timestamp>.txt
python -m spaec_manager place spec.yaml

# с настройкой бюджета поиска и явным именем файла отчёта
python -m spaec_manager place spec.yaml --time-budget 30 --out result.txt
```

Параметры (задел):
- `--time-budget <sec>` — бюджет времени поиска.
- `--seed <int>` — воспроизводимость случайных/эвристических выборов.
- `--node-budget <int>` — бюджет числа узлов DFS.
- `--out <file>` — имя файла для сохранения полного отчёта. Отчёт
  **всегда** сохраняется в текстовый файл: при заданном `--out FILE` —
  в указанный файл, иначе — по умолчанию в `result-<timestamp>.txt`
  (формат timestamp: `YYYYmmdd-HHMMSS`) в текущем рабочем каталоге запуска.

Полный отчёт при этом выводится и в stdout вместе со строкой
`Сохранено: <путь>`. При ошибке входа (exit 2) файл не создаётся.

## 3. ASCII-карта результата

Рендер сетки, где:
- символ типа (из реестра) — клетка кластера;
- `*` — заблокированная клетка;
- `.` — свободная клетка.

Пример фрагмента (сетка 10×10, угол 2×2 заблокирован):

```
**RRRCCC..
**RRRCCC..
.RRRCCCCC.
..........
..........
..........
..........
..........
..........
..........
```

> Замечание: два соприкасающихся кластера одного типа рендерятся одинаковым
> символом (например, обе комнаты — `R`). Визуально их не развести; поэтому
> различение идёт через таблицу отчёта и координаты каждого экземпляра.

## 4. Таблица «запрошено / фактически / отклонение»

По каждому размещённому кластеру:

| id | type | доля (%) | цель (клеток) | факт (клеток) | отклонение | статус |
|---|---|---|---|---|---|---|
| room1 | ROOM | 30 | 29 | 30 | +1 | ок |
| room2 | ROOM | 30 | 29 | 25 | −4 (−14%) | недостача |
| corridor1 | CORRIDOR | 40 | 38 | 38 | 0 | ок |

- «цель» = `round(F * areaPercent / 100)`.
- «отклонение» = факт − цель (в клетках и/или % от цели).
- «статус»: ок / недостача / превышение.

## 5. Предупреждения

При существенной недостаче площади кластера система **обязана** явно предупредить, напр.:

```
WARNING: room2 (ROOM) получился меньше запрошенного: 25 клеток вместо цели 29 (-14%).
         Полностью вписать кластер в заданную долю не удалось.
```

Порог «существенности» фиксируется при кодировании (см. [05-solver-design.md](./05-solver-design.md) §6).

## 6. Сообщение о невозможности размещения

При `feasible=False` — понятный вывод с причиной:

```
НЕ УДАЛОСЬ РАЗМЕСТИТЬ ВСЕ КЛАСТЕРЫ.
Причина: кластер corridor1 (shape=circle, цель=38 клеток) не помещается:
  свободная область не содержит связного фрагмента достаточного размера/формы.
Рассмотрите: уменьшение доли, смену shape на free, или расширение области.
```

Возможные причины — см. [05-solver-design.md](./05-solver-design.md) §7.

## 7. Выходной код процесса (задел для автоматизации)

- `0` — размещение найдено (возможно, с предупреждениями о мягких отклонениях);
- `1` — не удалось разместить (жёсткая невозможность);
- `2` — ошибка входных данных (валидация спеки/файлов).
