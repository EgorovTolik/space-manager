# 03. Формат спецификации размещения (вход)

> Сводный индекс: [../README.md](../README.md) · Модель: [02-domain-model.md](./02-domain-model.md)

Вход системы — это **YAML-спекация** плюс до двух опциональных текстовых файлов
(маска блокировок и предзаполненная карта). Ниже — полное поле-в-поле описание.

## 1. YAML-спекация: полный пример

```yaml
# =====================================================================
# СПЕКАЦИЯ РАЗМЕЩЕНИЯ — один файл = один запрос размещения на одной сетке.
# Три смысловых блока: grid (+блокировки), types + rules, clusters.
# =====================================================================

grid:
  width: 10              # число колонок по X (клетки). Целое > 0.
  height: 10             # число строк по Y (клетки). Целое > 0.

blockedFile: ./blocked.txt   # (опционально) маска блокировок, см. §2.
                             # Если не задан — блокировок нет.

presetFile: null           # (опционально) предзаполненная карта кластеров, см. §3.
                           # null = нет предзаполнения.

# ---------------------------------------------------------------------
# РЕЕСТР ТИПОВ — «заранее известные» типы системы (описываются один раз).
# Ключ  = id типа (используется в clusters и rules.adjacency).
# symbol = символ, которым тип рисуется на карте-результате.
# name   = опциональное человекочитаемое имя.
# ---------------------------------------------------------------------
types:
  ROOM:     { symbol: "R", name: "Комната" }
  CORRIDOR: { symbol: "C", name: "Коридор" }
  WALL:     { symbol: "#", name: "Стена" }

# ---------------------------------------------------------------------
# ПРАВИЛА РАЗМЕЩЕНИЯ (ruleset) — системный уровень, общий для всех кластеров.
# Подробная семантика: [04-rules-and-adjacency.md](./04-rules-and-adjacency.md).
# ---------------------------------------------------------------------
rules:
  connectivity: 8          # режим связи/соседства: 4 = по ребру, 8 = + диагонали.
                           # Текущий срез задачи: 8.

  adjacency:               # принципы соседства между РАЗНЫМИ типами.
    forbidden:             # пары типов, которым ЗАПРЕЩЕНО соприкасаться (blacklist).
      - [ROOM, WALL]       # всё остальное разрешено по умолчанию (default-open).
    allow: null            # (опционально) ЖЁСТКИЙ whitelist: если задан,
                           # разрешены только перечисленные пары. null = default-open.

  size:                    # ОБЯЗАТЕЛЬНЫЕ (жёсткие) границы размера одного кластера.
    min: null              # минимальное число клеток; null = нет жёсткого минимума.
    max: null              # максимальное число клеток; null = без ограничения.

  convexity:
    weight: soft           # предпочтение выпуклых форм. Текущий срез: soft (штраф).
                           # hard = отклонять вогнутые формы (не реализовано сейчас).

  fillAll: false           # true = использовать всю доступную площадь,
                           # лишнее распределяется пропорционально долям.
                           # false = остаток остаётся свободным.

  touchAll: false          # true = все кластеры обязаны примыкать друг к другу
                           # (8-окрестность): граф «кластер → кластер» связан,
                           # зазоров между кластерами нет. Жёсткое условие:
                           # если разместить невозможно — ошибка с причиной.
                           # false (по умолчанию) = кластеры могут быть разнесены.

# ---------------------------------------------------------------------
# ЗАПРОС — конкретные кластеры к размещению.
# Каждый элемент = ОДНО помещение/кластер. Повтор типа = РАЗНЫЕ объекты,
# все подчинены общим правилам из блока rules.
# ---------------------------------------------------------------------
clusters:
  - id: room1                    # человекочитаемый id экземпляра (уникальный в запросе).
    type: ROOM                   # тип из реестра types.
    areaPercent: 30              # доля от доступной площади F (число 0..100].
    shape: free                  # free | rectangle | circle, см. §4.

  - id: room2                    # повтор типа ROOM = второе отдельное помещение.
    type: ROOM
    areaPercent: 30
    shape: free

  - id: corridor1
    type: CORRIDOR
    areaPercent: 40              # Сумма долей должна быть <= 100.
    shape: circle                # здесь кластер должен получиться «круглым».
```

## 2. Файл маски блокировок (`blockedFile`)

- Текстовый файл, **размером ровно `width × height`** (как в разделе `grid`).
- Каждая строка — ровно `width` символов; строк — ровно `height`.
- Символ `*` = **заблокированная** клетка (в неё нельзя ставить кластеры).
- Любой другой символ (пробел, `.`, `-`) = **свободная** клетка.
- Блокировки **не вычитаются из базы процентов**: «100% площади для заполнения»
  — это количество свободных (незаблокированных) клеток.

Пример `blocked.txt` для сетки 10×10 с заблокированным левым верхним углом 2×2:

```
**........
**........
..........
..........
..........
..........
..........
..........
..........
..........
```

Здесь свободных = 96 → это и есть «100%» для расчёта долей.

## 3. Файл предзаполненной карты (`presetFile`)

- Опциональный. Тот же размер `width × height`.
- В клетках, где уже стоит символ типа из реестра, — **неподвижный** кластер:
  его нельзя двигать, и в его пиксели нельзя ставить другие кластеры.
- Свободные клетки — любой символ, не совпадающий с символами типов (напр. `.`).
- Если тип встречается несколькими связными группами в одном preset — каждая
  группа считается отдельным неподвижным кластером того типа.

> Мелкое уточнение на этапе реализации: как preset влияет на расчёт базы F и
> целевых площадей, фиксируется при кодировании (по умолчанию база = «не блокировки»,
> а preset — жёсткое ограничение «не перекрывать»). См. [05-solver-design.md](./05-solver-design.md) §6.

## 4. Значения поля `shape`

| Значение | Смысл |
|---|---|
| `free` | любая связная форма; солвер выбирает сам, предпочитая выпуклые (см. [05](./05-solver-design.md) §5). |
| `rectangle` | сплошной осевой прямоугольник `w × h` без «дыр». |
| `circle` | приближение круга: все клетки в радиусе `R` от целочисленного центра. Точный круг из пикселей не существует — допустимы небольшие отклонения по границе (см. [05](./05-solver-design.md) §4). |

## 5. Валидация входа (ошибки на этапе парсинга)

Система должна отклонить спекацию с понятным сообщением, если:
- `width`/`height` не положительные целые;
- файл блокировок не совпадает по размеру с `grid`;
- в `clusters` указан тип, которого нет в `types`;
- дублируется `id` экземпляра в пределах одного запроса;
- `Σ areaPercent > 100`;
- в `adjacency.forbidden`/`allow` указаны неизвестные типы;
- `shape` не входит в допустимый набор;
- `touchAll` не является boolean.
