# 01. Постановка задачи

> Часть документации проекта **space-manager** (система размещения кластеров на сетке).
> Сводный индекс и мастер-бриф: [../README.md](../README.md)

## 1. Суть

Нужно реализовать механизм размещения **замкнутых кластеров** на общем пространстве,
которое задаётся прямоугольной «пиксельной» сеткой. Каждая ячейка сетки может
принадлежать одному из известных типов кластеров (обозначается символом типа),
быть свободной или заблокированной.

Система получает:
- набор **заранее известных типов** кластеров;
- **произвольное описание желаемых размещений** (какие кластеры, каких долей площади,
  какой формы разместить на заданной области).

Задача системы — на предоставленной области **разместить указанные кластеры в
соответствии с правилами размещения и принципами соседства**. Если разместить
невозможно — честно сообщить пользователю об этом (с указанием причины).

## 2. Реальная метафора

Кластеры можно понимать как «помещения» на плане: комнаты, коридоры, стены.
Пользователь задаёт площадь и доли под каждое помещение; система укладывает их
на сетку так, чтобы соблюдались правила соседства (что может с чем граничить)
и формы были приемлемыми.

> Примечание: в более раннем обсуждении рассматривалась **вложенность**
> («комната, окружённая коридором со всех сторон»). На текущем этапе
> вложенность **полностью исключена**: кластеры могут только *граничить*
> друг с другом. Механизм вложенности вынесен в будущие расширения (см. §6).

## 3. Ключевые свойства кластеров

- Кластер — это **связная область** ячеек одного типа. Связность и «соседство»
  определяются по **8-окрестности** (ортогональ + диагонали).
- **Слияния нет.** Два кластера одного типа, даже если они соприкасаются,
  остаются двумя отдельными объектами. Поэтому внутренняя модель хранит в
  ячейке **идентификатор экземпляра кластера**, а не просто символ типа.
  Символ — лишь отображение типа при рендере.

## 4. Что делает система (ввод/вывод)

- **Ввод:** спекация размещения (YAML) + маска блокировок (текстовый файл) +
  (опционально) предзаполненная карта кластеров. Подробнее: [03-placement-spec.md](./03-placement-spec.md).
- **Выход:** ASCII-карта результата + таблица «запрошено / фактически / отклонение»
  по каждому кластеру + предупреждения о недостаче площади или диагностика причины
  невозможности размещения. Подробнее: [06-io-and-reporting.md](./06-io-and-reporting.md).

## 5. Ограничения и допущения (текущий срез)

1. Связность/соседство — по **8-окрестности**.
2. **Вложенность запрещена** на этом этапе. Кластеры только граничат друг с другом.
3. Повтор типа в запросе = **разные отдельные кластеры**, все подчинены общим правилам.
4. Площади задаются **долями (в процентах) от доступной площади**. Цели — **мягкие**:
   система стремится приблизиться к долям, но может увеличить/уменьшить площадь;
   при недостаче — обязательно предупреждает пользователя.
5. Заблокированные пиксели передаются отдельным текстовым файлом и **не входят**
   в базу «100%» доступной площади.
6. Пользователь может передать предзаполненную карту: её кластеры **неподвижны**.
7. Достаточно найти **одно** размещение (без поиска множества вариантов).

## 6. Вне текущего среза (на будущее)

- Вложенность кластеров («матрёшка») и правила на глубину/тип контура.
- Оптимизация «лучшего» размещения или выдача нескольких альтернатив.
- Расширенные формы (произвольные полиомино-шаблоны).
- SAT-энкодинг для крупных сеток (текущий солвер — backtracking, см. [05-solver-design.md](./05-solver-design.md)).
