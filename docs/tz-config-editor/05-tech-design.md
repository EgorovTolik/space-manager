# 5. Технический дизайн

## 5.1 Стек

| Слой | Технология |
|---|---|
| UI | React 18 + TypeScript, Vite |
| Стили | Tailwind CSS (тёмная тема по умолчанию) |
| YAML-парсинг/сериализация | `yaml` (npm) — сохраняет порядок ключей и поддерживает комментарии при raw-режиме |
| Бэкенд | Node.js + Express: отдача статики (`web/dist`), dev-прокси Vite. **Доступ к диску проекта не выполняет** (модель «загрузил — скачал»); структура оставляет место для будущих API (например, запуск решателя) |
| Хранение черновика | `localStorage` клиента (FR-18) |

Проект разворачивается как отдельный компонент рядом с `space-manager` (например, поддиректория `editor/` или отдельный репозиторий — решение на стороне инфраструктуры; ТЗ не привязывает).

## 5.2 Архитектура приложения

```
┌────────────────────────── Frontend (SPA) ──────────────────────────┐
│  Views: EmptyState │ WorkArea (SidePanel + GridView/SectionForm)   │
│  State:  SetStore (единый store комплекта)                         │
│            ├── spec: SpecModel                                     │
│            ├── mask?: { w, h, cells: Uint8Array }                  │
│            └── preset?: { w, h, cells: Uint8Array }                │
│  Core:   validator.ts (V1–V11) · io.ts (parse/serialize)          │
│          history.ts (undo/redo) · colors.ts                        │
└─────────────────────────────────────────────────────────────────────┘
```

## 5.3 Модель состояния

- **SpecModel** — типизированное отражение YAML: `grid {width, height}`, `blockedFile?: string | null`, `presetFile?: string | null`, `types: Record<string, {symbol, name}>`, `rules` (структура §2.1), `clusters: Cluster[]`. Все мутации — через действия store (для undo/redo и валидации).
- **Маска** — `Uint8Array(w·h)`: 0 = `.`, 1 = `*`.
- **Пресет** — `Uint8Array(w·h)`: 0 = `.`, иначе индекс типа в текущем списке палитры (индексы переживают перестановку типов через стабильный id типа).
- **Палитра** — производная от `spec.types`; при работе без спеки — собственный список «на лету» (FR-14), который при экспорте вливается в `types`.
- **Имена файлов** — `{ specName, maskName?, presetName? }`, запоминаются при загрузке (FR-5).

## 5.4 Чтение и запись файлов

### Парсинг
- YAML → `SpecModel` через `yaml.parse`; ошибки парсинга показываются с номером строки.
- Маска/пресет: проверка размеров (строки × символы), допустимых символов; для пресета — построение карты «символ → тип» (неизвестные символы без спеки создают временные типы).

### Сериализация
- **Спека**: генерация YAML из `SpecModel` с каноническим порядком ключей (`grid, blockedFile, presetFile, types, rules, clusters`) и 2-пространственным отступом — как в `examples/`. Raw-режим (FR-10): при ручном изменении исходника он хранится отдельно и выгружается как есть после повторного успешного парсинга.
- **Маска/пресет**: построчная сборка строк из символов, `\n` в конце файла.

### Экспорт
Скачивание — `Blob` + `<a download>`; «скачать всё» — три последовательных скачивания (ZIP не требуется в v1).

## 5.5 Валидация

Модуль `validator.ts`: чистая функция `(set: SetState) → Issue[]`, где `Issue = { level: 'error' | 'warning', code: 'V1'…'V11', message, target }`. Вычисляется реактивно (memo) при каждом изменении состояния; результаты питают панель валидации и флаг «экспорт разрешён».

## 5.6 Отрисовка сетки

- **До 128×128**: CSS Grid (`display: grid`, размер клетки = параметр zoom, по умолчанию автоподбор под контейнер). Простота, доступность, нативные события на клетках.
- **Больше / тяжёлые сценарии**: отрисовка `<canvas>` с маппингом координат мыши → клетка; drag-раскраска батчится в `requestAnimationFrame`.
- Drag-раскраска: `pointerdown` → серия `pointermove` (throttle до rAF) → `pointerup`; одна «транзакция» = один шаг undo.
- Требования производительности: 50×50 — без задержек; 200×200 — плавный zoom и раскраска (FR-12).

## 5.7 Undo/Redo (FR-17)

- История хранится в памяти (не в localStorage): стек состояний `{mask | preset | spec-section}`, ≥ 50 шагов, LRU-отсечение.
- Точки записи: завершение drag-транзакции, кнопка «очистить/заполнить всё», изменения форм разделов спеки (по blur/применению).

## 5.8 Черновик в localStorage (FR-18)

- Автосохранение всего комплекта (spec + mask + preset + names) с дебаунсом 2 c; ключ — `editor.draft.v1`; при восстановлении — баннер «восстановлен черновик от …» с кнопками «продолжить / сбросить».
- Ограничение размера: комплект до ~200×200 (~40 КБ в base64/Array) — комфортно для `localStorage`.

## 5.9 Тестирование

| Уровень | Что покрываем | Инструменты |
|---|---|---|
| Юнит | `io.ts`: парсинг/сериализация всех файлов `examples/` (snapshot: выгруженный YAML эквивалентен исходному по данным; маска/пресет — побитово) | Vitest |
| Юнит | `validator.ts`: каждый код V1–V11, happy + edge (0, 100, сумма > 100, коллизия символов) | Vitest |
| Юнит | history/undo-redo инварианты | Vitest |
| Компонентный | PixelGrid: paint/erase/drag; PaletteEditor: создание на лету | Vitest + Testing Library |
| E2E (минимально) | Сценарии С1–С3 из 04.2 (открыть → правка → экспорт) | Playwright |

**Критерий соответствия формату (главный):** для каждого `examples/spec_*.yaml` + связанных файлов «загрузить → не менять → скачать» даёт файлы, на которых решатель выдаёт идентичный результат размещения.

## 5.11 Отложенные расширения (не в v1)

- Серверный доступ к директории проекта (редактирование файлов «на месте» без скачивания).
- Запуск решателя из редактора и просмотр `result-*.txt` поверх сетки.
- Экспорт комплекта одним ZIP-архивом.
- Импорт/экспорт самого черновика (portable draft).
