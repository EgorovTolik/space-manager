# 3. Функциональные требования

Приоритеты: **P0** — обязательно в v1; **P1** — желательно в v1, допустимо перенести в v1.1; **P2** — позже.

## 3.1 Работа с комплектом файлов

### FR-1. Загрузка существующего комплекта (P0)
Пользователь загружает файл спеки (drag&drop или выбор файла). Приложение:
1. Парсит YAML и отображает комплект.
2. Если в спеке указаны `blockedFile`/`presetFile` — запрашивает у пользователя соответствующие файлы (с подсказкой ожидаемого имени) и подгружает их; если пользователь пропускает — отмечает ссылку как «файл не загружен» (V11).

**Приёмка:** загрузка каждого файла из `examples/` (`spec_basic.yaml`, `spec_touchall.yaml` + маски/пресеты) без ошибок; комплект отображается корректно.

### FR-2. Загрузка файлов по отдельности (P0)
Маска или пресет могут быть загружены без спеки: приложение создаёт временный контекст — сетку размером с файл, для пресета — временную палитру из найденных символов (созданную на лету, см. FR-6).

**Приёмка:** загрузка `blocked_basic.txt` и `preset_example.txt` по отдельности; дальнейшее редактирование возможно; при сохранении спеки для такого комплекта приложение создаёт её с соответствующими `types` (для пресета) либо запрашивает имя/размеры.

### FR-3. Создание нового комплекта с нуля (P0)
Сценарий «новый комплект»: диалог задаёт `width`, `height` (с валидацией V1). Создаётся пустая спека (без типов, без кластеров, `rules` — значения по умолчанию: `connectivity: 8`, `adjacency.forbidden: []`, `adjacency.allow: null`, `size: {min: null, max: null}`, `convexity.weight: soft`, `fillAll: false`, `touchAll: false`) + пустая маска (все `.`) + пустой пресет (все `.`).

**Приёмка:** из диалога «создать» в два-три действия получается редактируемый комплект; экспорт сразу доступен.

### FR-4. Экспорт / скачивание файлов (P0)
Кнопки: «Скачать спеку», «Скачать маску», «Скачать пресет». Имя файла — как было при загрузке либо как в `blockedFile`/`presetFile`, либо задаётся пользователем; для нового комплекта — диалог имён (предполагаемые: `spec.yaml`, `blocked.txt`, `preset.txt`). Экспорт маски/пресета доступен только если соответствующий файл существует в комплекте; при наличии ошибок валидации (уровень «ошибка») экспорт заблокирован, список ошибок показан.

**Приёмка:** скачанные файлы открываются решателем `space-manager` без изменений формата: `python -m spaec_manager place <выгруженная_спека>` для каждого примера из `examples/` даёт тот же результат размещения, что исходный файл.

### FR-5. Сохранение пути и имени (P1)
При загрузке приложение запоминает исходные имена файлов; при экспорте использует их по умолчанию.

## 3.2 Редактор спеки

### FR-6. Раздел «Сетка» (P0)
Поля `width`, `height`: числовые инпуты, целые > 0. При изменении размеров — маска и пресет **строго не обрезаются молча**: приложение показывает диалог с вариантами (обрезать / дополнить краями `.` / отменить).

**Приёмка:** изменение 12×8 → 15×10 с подтверждением; после дополнения файлы проходят V8.

### FR-7. Раздел «Типы» (P0)
Список типов: строки `КЛЮЧ`, `symbol`, `name` + кнопка удаления; кнопка «добавить тип». Валидация V2 при вводе (символ — один, уникальность). Смена `symbol` типа синхронно подменяет символы в пресете (если он загружен) либо предупреждает о расхождении.

**Приёмка:** добавление/переименование/удаление типа; удаление типа, используемого кластером или пресетом, — блокируется с пояснением (или предлагает массовую замену).

### FR-8. Раздел «Кластеры» (P0)
Список кластеров с колонками: `id`, `type` (выпадающий из `types`), `areaPercent`, `shape` (free/rectangle/circle); кнопки: добавить, удалить, переместить вверх/вниз. Валидация V3–V7. Показ подсказки «цель = round(F · p / 100)» рядом с полем при известной F (маска загружена).

**Приёмка:** полный CRUD кластеров; создание кластера со ссылкой на несуществующий тип невозможно через UI; экспортированный список идентичен по смыслу исходному.

### FR-9. Раздел «Правила» (P0)
Форма известных правил: `connectivity` (4/8), `adjacency.forbidden` (список пар типов, добавление/удаление), `adjacency.allow` (null или список пар), `size.min/max`, `convexity.weight`, `fillAll`, `touchAll`.

**Приёмка:** редактирование всех полей; экспорт специки с изменёнными правилами читается решателем.

### FR-10. Raw-режим YAML (P1)
Переключатель «показать исходный YAML»: синхронизированный текстовый редактор всего файла (применяется по кнопке, с валидацией и сообщением об ошибках парсинга). Служит обходным путём для любых нестандартных/неизвестных полей.

**Приёмка:** вставка внешнего YAML со специфичными полями не приводит к их потере при выгрузке.

## 3.3 Визуальный редактор маски

### FR-11. Сетка маски (P0)
Отрисовка grid W×H: свободная клетка — светлая, заблокированная — тёмная/контрастная. Инструменты: **кисть** (`*`), **ластик** (`.`); расстановка кликом и протяжкой (drag). Кнопки: «очистить всё», «заблокировать всё». Статистика: число заблокированных клеток и `F`.

**Приёмка:** маски из `examples/` открываются и совпадают с файлом побитово; ручная перерисовка 50×50 плавная (без задержек > 100 мс на клик).

### FR-12. Масштаб отрисовки (P1)
Регулировка размера клетки (zoom) для больших сеток; поддержка комфортной работы до 200×200.

## 3.4 Визуальный редактор пресета

### FR-13. Сетка пресета и палитра (P0)
Отрисовка grid: незакрашенная клетка — нейтральная; закрашенная — цветом типа с символом. **Палитра**: типы текущей спеки (символ, имя, цвет); выбор «кисти» = тип или ластик. Расстановка кликом/протяжкой. Статистика: занятость по типам (число клеток).

**Приёмка:** `preset_example.txt` открывается побитово корректно; раскраска символом типа и стирание работают; при 50×50 без просадок.

### FR-14. Палитра «на лету» (P0)
Если спеки нет или в ней нет типов, пользователь может прямо в палитре создать новый тип (символ + имя); созданные типы попадают в `types` спеки при её создании/экспорте (см. FR-2).

**Приёмка:** из загруженного только пресета можно добавить новые типы и экспортировать полный комплект.

### FR-15. Цвета типов (P0)
Каждому типу автоматически назначается различимый цвет (детерминированно от ключа); пользователь может выбрать цвет вручную. Цвет существует **только в UI** — в файлы не выгружается.

## 3.5 Общие требования к приложению

### FR-16. Панель валидации (P0)
Список ошибок/предупреждений (V1–V11) с переходом к проблемному разделу; ошибки блокируют экспорт, предупреждения — нет.

### FR-17. Undo/Redo для пиксельных редакторов (P1)
История изменений маски и пресета (не менее 50 шагов), Ctrl+Z / Ctrl+Shift+Z; изменение размера сетки очищает историю соответствующего редактора.

### FR-18. Сброс состояния без потери данных (P0)
Перезагрузка страницы не должна приводить к потере несохранённого комплекта: состояние сериализуется в `localStorage` и восстанавливается при открытии (с уведомлением «восстановлен черновик»).

### FR-19. Тёмная тема, адаптивность (P0)
Интерфейс в тёмной теме; рабочая ширина от 1024 px (десктоп); мобильный режим не требуется.
