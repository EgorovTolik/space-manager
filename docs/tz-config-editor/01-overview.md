# 1. Обзор

## 1.1 Назначение

Веб-редактор — отдельный компонент общей системы, обеспечивающий **человеко-ориентированное создание и редактирование** конфигурационных файлов проекта `space-manager`:

- **спека размещения** (`spec_*.yaml`) — сетка, типы, правила, список кластеров;
- **маска заблокированных клеток** (`blocked_*.txt`) — текстовая сетка `*` / `.`;
- **пресет предзаполнения** (`preset_*.txt`) — текстовая сетка с символами типов.

Без редактора эти файлы создаются вручную в текстовом виде: для сеток 50×50 и выше это неудобно, ошибкоёмко и не даёт визуального контроля.

## 1.2 Место в общей системе

```
┌─────────────────────┐        ┌──────────────────────┐
│   Веб-редактор      │  файлы │   space-manager      │
│ (этот компонент)    ├───────▶│ (решатель/генератор) │
└─────────────────────┘ скач.  └──────────────────────┘
        ▲ «загрузил — отредактировал — скачал»
```

- Редактор **не запускает** решатель и не имеет к нему обращения: результат работы редактора — готовые файлы, которые пользователь помещает в проект и запускает `space-manager` самостоятельно.
- Файлы, создаваемые/редактируемые редактором, — это те же форматы, что в `examples/` проекта (см. документ 02).
- Случайная генерация раскраски, размещение кластеров по правилам — **не задача редактора** (делает `space-manager`).

## 1.3 Границы продукта

**Входит:**
- загрузка спеки и/или маски и/или пресета (по отдельности или комплектом);
- создание нового комплекта с нуля;
- полное редактирование всех полей спеки (включая `rules`);
- визуальное (пиксельное) редактирование маски и пресета;
- создание/изменение/удаление типов «на лету» (для пресета без спеки — и как палитры);
- список кластеров: создание, редактирование, удаление, перестановка;
- валидация с понятными сообщениями; экспорт файлов скачиванием.

**Не входит (non-goals):**
- блокировки файлов, конкурентность, многопользовательский режим, аутентификация;
- серверное хранение файлов и доступ к диску проекта (в v1 — только «скачал обратно»);
- запуск/интеграция с решателем `space-manager`;
- генерация раскраски/размещения (случайная пятнами, авто-кластеризация и т.п.);
- просмотр результата размещения (`result-*.txt`) — возможна позже как отдельная фича.

## 1.4 Термины

| Термин | Определение |
|---|---|
| **Сетка (grid)** | Прямоугольное поле `width × height` клеток, на котором размещаются кластеры. |
| **Клетка** | Единичный пиксель сетки; в маске — `*` (заблокирована) или `.` (свободна); в пресете — символ типа или `.` (не задана). |
| **Маска (blocked-файл)** | Текстовый файл W×H с заблокированными клетками (`*`). Ссылается из спеки полем `blockedFile`. |
| **Пресет (preset-файл)** | Текстовый файл W×H, где отдельные клетки заранее заняты символами типов. Ссылается из спеки полем `presetFile`. |
| **Тип** | Именованный класс клеток (`types.<KEY>`): однобуквенный `symbol` + человекочитаемое `name`. |
| **Кластер** | Запись списка `clusters` спеки: `id`, `type`, `areaPercent`, `shape` — цель, которую решатель должен разместить. |
| **Комплект** | Связка «спека + 0/1 маска + 0/1 пресет» — базовая единица работы редактора. |
| **F (доступная площадь)** | Число свободных клеток сетки после вычета маски: `width·height − blocked`. |

## 1.5 Пользователи

Один пользователь, локальный запуск. Интерфейс — русский язык.
