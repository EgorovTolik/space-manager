Язык: **Python** (3.10+). Ниже — структура пакета, разбиение на модули-подзадачи
и этапы. Каждый модуль — отдельная подзадача, которую можно делегировать субагенту

## 2. Модули ↔ подзадачи (порядок реализации)

| № | Подзадача / модуль | Зависимости | Критерий готовности |
|---|---|---|---|
| 1 | `models.py` — доменная модель | — | dataclass'ы из [02](./02-domain-model.md) создаются; типизация проходит |
| 2 | `spec_io.py` — парсинг и валидация | models | корректно читает YAML + blocked (+preset); отклоняет невалидный вход с понятной ошибкой (см. [03](./03-placement-spec.md) §5) |
| 3 | `rules.py` — валидаторы/оценщики | models | связность(8), rect, circle, fill_ratio, adjacency_ok работают; покрыты тестами |
| 4 | `report.py` — рендер и отчёт | models, rules | строит ASCII-карту + таблицу + предупреждения + причину невозможности (см. [06](./06-io-and-reporting.md)) |
| 5 | `solver.py` — поиск размещения | models, rules, report | находит валидное размещение для базовых примеров; сообщает причину при невозможности (см. [05](./05-solver-design.md)) |
| 6 | `cli.py` + интеграция | всё выше | `python -m space_manager place spec.yaml` работает сквозным образом (end-to-end), exit-codes по [06](./06-io-and-reporting.md) §7 |

> Модули 1–4 можно делать раньше солвера: модель + рендер дают видимый результат
> (карта), что удобно для проверки на ранних этапах.

## 3. Этапы (milestones)

- **M1 — Скелет и данные.** `models.py` + `spec_io.py`. Можно прочитать спекацию
  и построить сетку с блокировками/preset. Тесты парсинга.
- **M2 — Правила и рендер.** `rules.py` + `report.py`. Можно отрендерить заданную
  (напр. preset) карту и проверить валидаторы форм/связности.
- **M3 — Солвер.** `solver.py`. Размещение для базовых примеров; диагностика невозможности.
- **M4 — CLI и отчётка.** `cli.py`, examples, сквозной тест: спекация → карта + таблица.

## 4. Тестирование

- Unit по каждому чистому валидатору/оценщику (`rules.py`).
- Парсинг: валидные и невалидные спекации (красные тесты на валидацию).
- Солвер: набор эталонных примеров с известным результатом (помещается / нет,
  и почему), проверка idempotence при `--seed`.
- Интеграция: end-to-end от YAML до текста отчёта.

## 5. Зависимости

- `PyYAML` — парсинг спекаций.
- Всё остальное — стандартная библиотека Python (dataclasses, argparse, typing).
- Опционально (на будущее): SAT-солвер для крупных сеток (см. [05](./05-solver-design.md) §8).

## 6. Открытые уточнения для этапа кодирования

Собираем сюда мелкие решения, которые сознательно отложили из проектного
обсуждения (см. также [05](./05-solver-design.md) §6):

- дефолтный бюджет поиска и параметры CLI.
