# 05. Валидация

> Сводный индекс: [../docs-editor/README.md](./README.md) · Модель данных:
> [02-data-model-formats](./02-data-model-formats.md) · UI-подсветка: [04-ui-ux](./04-ui-ux.md) §7

Валидация выполняется **на клиенте** (модуль `lib/validation.ts`, [01-architecture](./01-architecture.md) §2.1).
Функция ядра: `validateAll(state: EditorState): ValidationError[]`, где

```ts
interface ValidationError {
  code: string;        // V-* из таблицы §2
  message: string;     // текст на русском, для баннера (04-ui-ux §7)
  field?: string;      // путь к полю модели, напр. 'clusters[1].areaPercent'
  cells?: [number, number][];  // клетки сетки для подсветки (04-ui-ux §3.5)
}
```

Валидация — **информационная** (soft gate): она не блокирует редактирование, но подсвечивает
ошибки и требует подтверждения при скачивании (§3). Это осознанно: пользователь может
скачать «сырой» файл; окончательный арбитраж формата — существующая система
`spaec_manager` (exit 2 на невалидном входе, docs/06 §7).

## 1. Порядок действий пользователя (workflow)

**Решение:** обязательная последовательность: **спекация → маски**. До загрузки/создания
спеки маски редактировать нельзя (нет grid для размера и реестра типов для preset-палитры).
При загрузке спеки, если маски уже загружены — они не сбрасываются, но перепроверяются по
новому grid/types.

## 2. Перенос правил docs/03 §5 (1:1) + правила масок

### 2.1 Ошибки YAML-спеки (аналог errors парсинга spaec_manager)

| Код | Правило (docs/03 §5) | Условие срабатывания в редакторе |
|---|---|---|
| V-GRID-DIMS | `width`/`height` не положительные целые | при создании спеки и при ручном изменении W×H: не целое, ≤ 0 |
| V-MASK-DIM | файл блокировок/preset не совпадает по размером с `grid` | размер загруженной маски ≠ `spec.grid` (и обратное: grid изменился, маска осталась) — подсветка всей маски заглушкой (04-ui-ux §3.5) |
| V-CLUST-TYPE | в `clusters` указан тип, которого нет в `types` | `clusters[i].type ∉ keys(types)` (появляется после удаления типа каскадом отменённым / при ручном вводе — защита на модели) |
| V-CLUST-ID | дублируется `id` экземпляра | два элемента `clusters` с одинаковым `id` |
| V-CLUST-SUM | `Σ areaPercent > 100` | сумма по всем кластерам > 100 (epsilon 1e-9); подсказка в ClustersPanel (04 §4) |
| V-ADJ-TYPE | в `adjacency.forbidden`/`allow` указаны неизвестные типы | элемент пары ∉ keys(types) — появляется при удалении типа без каскада пар (UI делает каскад, 04 §5; код как защита модели) |
| V-SHAPE | `shape` не входит в допустимый набор | значение ≠ free/rectangle/circle (защита модели; в UI недостижимо) |
| V-TOUCHALL-TYPE | `touchAll` не boolean | значение ≠ boolean (защита модели; в UI — чекбокс) |

### 2.2 Ошибки масок при ЧТЕНИИ файлов

| Код | Правило | Комментарий |
|---|---|---|
| V-MASK-DIM | количество строк ≠ `height` или длина строки ≠ `width` | файл не открывается: сообщение с указанием фактического размера (docs/03 §2) |
| V-MASK-PRESET | клетка preset-карты содержит символ, не совпадающий ни с одним символом реестра `types` и не являющийся свободным (пробел/`.`/`-`) | клетки перечисляются в `cells[]`, подсветка красным пунктиром (04-ui-ux §3.5); файл при этом **загружается**, редактирование доступно — пользователь может исправить клетки ластиком и скачать; скачивание требует подтверждения |

### 2.3 Ошибки маски блокировок при чтении

Отсутствуют: чтение терпимое (`*` → blocked, иначе free), кроме размера (V-MASK-DIM).
**Решение:** недопустимых символов в маске блокировок по определению нет (docs/03 §2:
«любой другой символ = свободная клетка»).

### 2.4 Ошибки формы UI (блокирующие ввод, не коды V-*)

| Поле | Правило |
|---|---|
| `TypeDef.symbol` | ровно 1 символ; ≠ `.` и ≠ `*`; уникален среди типов — иначе форма не сохраняет (сообщение под полем). Внутренние коды проверок: V-TYPE-SYMDUP / V-TYPE-RESERVED (формовые, в баннер не попадают) |
| `TypeDef.id`, ключи `types` | не пустой; уникален; `[A-Za-z][A-Za-z0-9_]*` |
| `ClusterEntry.id` | не пустой; уникальный в `clusters`; рекомендуется `[A-Za-z][A-Za-z0-9_-]*` |
| `areaPercent` | число, 0 < x ≤ 100, до 2 знаков после запятой |
| `size.min/max` | целые ≥ 0 или пусто; min ≤ max (иначе V-SIZE в баннере) |

### 2.5 Кросс-масочные правила

| Правило | Реализация |
|---|---|
| Одна клетка не может быть одновременно заблокирована и preset'ом (docs/03 §2–§3: блокировка исключает кластер) | **Варианты:** А) при чтении двух файлов конфликт → ошибка V-MASK-CONFLICT; Б) в редакторе рисование игнорируется (§3.6 04-ui-ux), при скачивании маски блокировки клетки preset'а автоматически НЕ помечаются `*`. **Решение: А + Б**: при чтении — предупреждение со списком клеток (блокировка «выигрывает» в рендере, но ошибка видна); в canvas — запрет рисовать друг поверх друга; при сериализации каждая маска пишется из своих данных независимо |

## 3. Поведение UI при ошибках (сводка)

1. `ValidationBanner`: «Ошибки валидации (N)» → раскрывающийся список: код + message.
2. Сетка: подсветка клеток из `cells[]` (красный пунктир), заглушка при V-MASK-DIM.
3. Скачивание: маски — только с подтверждением, если есть ошибки этой маски; спека —
   всегда, с подтверждением при любых ошибках («Скачать как есть?»).
4. Кнопки не блокируются (кроме загрузки другой спеки без подтверждения о потере изменений).

## 4. Соответствие spaec_manager

Каждый код V-* из §2.1 имеет «двойника» в списке ошибок парсинга `spaec_manager`
(docs/03 §5, реализация `spec_io.py`, exit 2) — **требование к разработке**: таблица
соответствия поддерживается в unit-тестах ([06](./06-testing-acceptance.md) §2.3): для
каждого кода V-* существует невалидная спекация, которую и редактор (клиентская
валидация), и `spaec_manager` отклоняют по той же сути. Это гарантия того, что редактор
не пропустит в файл ошибку, которую система не примет.
