> [06-testing-acceptance](./06-testing-acceptance.md), [07-nfr-limits](./07-nfr-limits.md).

## 1. Цель

Реализовать локальный веб-редактор входных файлов проекта **spaec-manager**:

- YAML-спекация размещения (`spec.yaml` — формат: `docs/03-placement-spec.md`);
- маска блокировок (`blockedFile` — текстовая карта, символ `*`);
- предзаполненная карта preset-кластеров (`presetFile` — текстовая карта символами типов).

Сценарий пользователя: **загрузил файл → отредактировал в браузере → скачал обратно**.
Форматы файлов редактор **не меняет**: результат скачивания принимается существующей
системой `python -m spaec_manager place <spec.yaml>` без изменений.

## 2. Состав системы

| Компонент | Технология | Роль |
|---|---|---|
| Фронтенд (SPA) | React + Vite + TypeScript | всё состояние редактора, парсинг/валидация/сериализация, canvas-редактор сетки, UI на русском |
| Бэкенд | Node.js + Express | раздача собранного фронтенда, `GET /api/health`. Хранения файлов нет |

Подробности: [01-architecture](./01-architecture.md).

## 3. Зафиксированные вводные заказчика (приняты без обсуждения)

1. Стек: **React + Vite + TypeScript** (фронтенд), **Node.js + Express** (бэкенд);
   базовый сценарий «загрузил файл — отредактировал — скачал обратно».
2. Редактор **не запускает генерацию размещения** — только редактирование входных файлов.
3. **Без реестра проектов и БД**: файлы загружаются пользователем из файловой системы
   и скачиваются обратно; сервер между сессиями ничего не хранит.
4. **Один пользователь**, локальная работа на персональном ПК. Auth/мультиюзер — вне ТЗ,
   но архитектура их не исключает (API вынесено в отдельный слой).
5. Размер сетки **W×H произвольный** (задаётся в спеке); отображение — viewport со
   скроллом и смещением (панорамирование), зум — опция.
6. Язык интерфейса — **русский**; целевая платформа — десктоп, современные
   Chrome/Firefox/Safari.
7. Preset-кластеры рисуются символами типов из реестра `types` спеки: палитра
   preset-редактора строится из текущих типов.
8. Форматы скачиваемых файлов — **строго существующие** (YAML по docs/03, текстовые маски);
   новых форматов редактор не вводит.

## 4. НЕ цели (out of scope)

- Генерация/запуск солвера размещения и отображение результата — нет (вводная №2).
- Хранение проектов на сервере, реестр, версии файлов, БД — нет (вводная №3).
- Auth, роли, мультиюзер, конкурентное редактирование — нет (вводная №4).
- Мобильные/планшетные интерфейсы; оптимизация под сенсорный ввод — нет (вводная №6).
- Локализация кроме русского языка — нет.
- Редактирование файлов результата (`result-*.txt`) и отчётов — нет.
- Undo/Redo — **не входит в v1** (roadmap, см. [07-nfr-limits](./07-nfr-limits.md) §5).

## 6. Критерии приёмки проекта целиком (сводка)

Подробности и декомпозиция — в [06-testing-acceptance.md](./06-testing-acceptance.md):

1. **Round-trip**: загруженные без изменений файлы скачиваются обратно — маски
   побайтово идентичны, YAML эквивалентен по данным (порядок ключей по docs/03).
2. **Совместимость форматов**: результат редактирования масок и спеки принимается
   `python -m spaec_manager place` (exit 0 на валидных данных, exit 2 с понятной ошибкой
   на невалидных) — проверено сквозным сценарием.
3. **UI**: все панели [04-ui-ux](./04-ui-ux.md) работают по описанию; валидация на лету
   подсвечивает ошибки (список 1:1 c docs/03 §5, см. [05-validation](./05-validation.md)).
4. **Производительность**: сетка до 200×200 — плавное панорамирование/зум (> 30 FPS),
   отклик на клик ≤ 100 мс ([07-nfr-limits](./07-nfr-limits.md) §3).
5. **Тесты**: unit-тесты (Vitest) зелёные, покрытие валидатора и сериализатора ≥ 90%
   по строкам; e2e-сценарии из [06](./06-testing-acceptance.md) §3 проходят.
6. **Запуск**: `npm run build` + `npm start` (Express) открывает редактор в браузере;
   dev-режим `vite + express proxy` работает.
