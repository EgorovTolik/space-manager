# 03. API сервера (Node.js + Express)

> Сводный индекс: [../docs-editor/README.md](./README.md) · Архитектура:
> [01-architecture](./01-architecture.md) (решение о клиентской логике — §2.1)

## 1. Принцип

Парсинг, валидация и сериализация выполняются **на клиенте** ([01-architecture](./01-architecture.md) §2.1).
Сервер хранит между сессиями ничего (вводная №3) и не участвует в обработке файлов:
загрузка — из файловой системы пользователя через браузер, скачивание — Blob + `<a download>`.

**Решение:** API минимален — один эндпоинт health. Это зафиксировано как требование:
любой будущий серверный функционал (auth, проверка спеки Python-валидатором) добавляется
новыми эндпоинтами без изменения контракта существующих.

## 2. Эндпоинты

| Метод | Путь | Ответ | Назначение |
|---|---|---|---|
| `GET` | `/api/health` | `200` JSON: `{ "status": "ok", "version": "<версия editor из package.json>" }` | проверка доступности сервера; фронтенд вызывает при старте — если недоступен, показывает баннер «Сервер недоступен (только статика)» и продолжает работу: функциональность редактора от него не зависит |

Все пути `/api/*`, не указанные выше, → `404` JSON `{ "error": "<path> not found" }`.

**Статика и SPA-fallback:**

- `GET /` и прочие пути — статика из `editor/dist/` (сборка Vite), с корректными
  `Content-Type` и `Cache-Control: no-cache` для `index.html`, `max-age=31536000, immutable`
  для assets с хэшем;
- любой GET-путь без расширения, не совпадающий с файлом статики и не начинающийся с
  `/api/` → отдаётся `dist/index.html` (SPA-fallback, нужен для глубоких ссылок — v1
  их почти нет, но правило фиксируется).

**Ошибки:** JSON-оформление `{ "error": "<сообщение>" }`; `500` — непредвиденное исключение
(обёртка error-handler'а), сообщение без stack trace в тело ответа.

## 3. Dev-режим и CORS

**Dev** (vite + express параллельно):

- Vite dev-сервер: `http://localhost:5173`, HMR;
- Express: `http://localhost:3000`;
- **CORS не требуется**: в `vite.config.ts` настраивается proxy —
  `'/api' → 'http://localhost:3000'` (все запросы UI идут в один origin — на 5173).

**Prod:** статика и API — один сервер, один порт; CORS-заголовки не нужны.
Заголовок `Access-Control-Allow-Origin` в v1 **не выдаётся**; если будущее разделение
доменов понадобится — добавляется middleware (архитектурно не исключено, вводная №4).

## 4. Версионирование и ограничения сервера

- Версия редактора — из `package.json` (`version`), доступна через `/api/health`;
- Таймауты по умолчанию Node; тело запросов на сервере **не обрабатывается вообще**
  (нет POST/PUT в v1) — `body-parser` не подключается;
- Порт 3000, переопределяется переменной окружения `PORT`;
- Логи: консоль, уровень info (запросы статики — доступ по умолчанию Express'а);
- Ограничение на количество одновременных соединений — дефолтное Node.

## 5. Что явно НЕ входит в API v1

| Эндпоинт | Почему нет |
|---|---|
| `POST /api/spec/validate` (проверка через Python) | генерация/валидация сервером вне сценария (вводные №2, №3); клиентская валидация покрывает docs/03 §5 1:1 ([05-validation](./05-validation.md)) |
| `POST /api/upload`, `GET /api/files` | хранение файлов на сервере запрещено вводной №3 |
| `POST /api/place` (запуск солвера) | генерация вне редактора (вводная №2) |
