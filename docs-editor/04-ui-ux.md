# 04. UI/UX редактора

> Сводный индекс: [../docs-editor/README.md](./README.md) · Модель данных:
> [02-data-model-formats](./02-data-model-formats.md) · Валидация: [05-validation](./05-validation.md)

Язык интерфейса — русский (вводная №6). Платформа — десктоп, минимальный целевой размер
окна браузера 1280×768; вёрстка плотная, трёхколоночная. Все обозначения полей — те же,
что в [02](./02-data-model-formats.md) §1–2.

## 1. Экран «Панель файлов» (левая колонка, `FilesPanel`)

```
┌─────────────────────────────┐
│ ФАЙЛЫ                       │
├─────────────────────────────┤
│ Спекация:                   │
│ [📂 Загрузить spec.yaml]    │  ← обязательна первая; drag&drop или выбор файла
│   имя: spec_basic.yaml      │  ← статус: загружена / не загружена
│   размер: [50] × [50]       │  ← редактируемые W×H (целые > 0, см. ниже)
│ [＋ Создать спеку…]         │  ← диалог W×H (02 §7)
│                             │
│ Маска блокировок:           │
│ [📂 Загрузить] [＋ Добавить]│
│   имя: blocked_basic.txt    │  ← статус: загружена / нет / размер≠grid ⚠
│ [⬇ Скачать]                 │  ← активна, если маска есть
│                             │
│ Preset-карта:               │
│ [📂 Загрузить] [＋ Добавить]│
│   имя: preset_example.txt   │
│ [⬇ Скачать]                 │
├─────────────────────────────┤
│ ⚠ Ошибки валидации (3)      │  ← баннер, клик → список ошибок (05 §4)
└─────────────────────────────┘
```

Правила:

- **Порядок действий (вводная из [05](./05-validation.md) §1):** спекация загружается
  первой. До её загрузки/создания кнопки масок и правые панели неактивны (подпись:
  «Сначала загрузите спекацию»).
- Загрузка спеки **перезаписывает** всё текущее состояние редактора; если есть
  несохранённые изменения — диалог подтверждения («Текущие изменения будут потеряны»).
- Скачивание маски обновляет поле `blockedFile`/`presetFile` в модели спеки
  (правила — [02](./02-data-model-formats.md) §6).
- Кнопка скачивания спеки активна всегда, когда есть модель спеки; при первом
  скачивании изменённой спеки — предупреждение о потере комментариев ([02](./02-data-model-formats.md) §4, п.1).
- **Размер сетки:** поля W×H под статусом спеки редактируемы в любой момент
  (целые > 0; V-GRID-DIMS при невалидном значении). При изменении — маски
  пересоздаются: сохраняется пересечение со старым размером, клетки за новыми
  границами отбрасываются, новые клетки — свободные ([02](./02-data-model-formats.md) §1,
  action `GRID_RESIZE` в [01](./01-architecture.md) §2.7). Подсказка перед применением:
  «Изменение размера сетки: клетки масок вне нового размера будут потеряны» — с
  подтверждением, если что-то действительно отбрасывается.
- Статусы файлов (загружена/нет/размер не совпадает) пересчитываются на каждое
  изменение и дублируются в `ValidationBanner`.

## 2. Общая компоновка экрана

```
┌──────────┬──────────────────────────────────────────────┬─────────────────────┐
│ FilesPanel│  GridCanvas (центр, вся оставшаяся ширина)   │ Правая колонка:     │
│ (§1)      │                                              │ [Кластеры][Типы]    │
│           │  ┌ viewport: сетка, скролл/панорамирование ┐ │ [Правила] — табы    │
│           │  │  *RRR....                                │ (ClustersPanel,     │
│           │  │  RRRRCCCC                               │  TypesPanel,        │
│           │  └─────────────────────────────────────────┘ │  RulesPanel)       │
│           │                                              │                     │
│           │  панель инструментов (§3.2)                   │                     │
└──────────┴──────────────────────────────────────────────┴─────────────────────┘
```

Центральная область — одна, переключается двумя режимами маски (без перезагрузки).
Правые панели — табы; активный таб не влияет на `GridCanvas`, только режим рисования
определяется переключателем в самом canvas (§3.1) — чтобы не путать «что редактирую»
с «какой список смотрю».

## 3. Сетевой редактор (`GridCanvas`)

### 3.1 Режимы (переключатель над canvas)

| Режим | Что рисуется/редактируется | Цвета (канонические) |
|---|---|---|
| «Маска блокировок» | `blockedMask`; заблокированные клетки редактируются инструментами | клетка заблокирована — `#333333`; свободная — `#ffffff`; сетка линий — `#dddddd` |
| «Preset-кластеры» | `presetMask`; каждая preset-клетка имеет символ типа (палитра §3.3) | клетка free — `#f5f5f5`; preset-клетка — цвет из палитры символа; заблокированные клетки маски блокировок отображаются полупрозрачным серым фоном (`#cccccc`, 40%) как контекст — редактированию не подлежат |

Режим переключается только при загруженной соответствующей маске; если маски нет —
кнопка режима неактивна с подсказкой «Маска не загружена (см. панель Файлы)».

### 3.2 Инструменты (панель над canvas)

| Инструмент | Действие (клик/драг) | Ключ |
|---|---|---|
| Кисть | в blocked-режиме: поставит/снимет `*` по клеткам; в preset-режиме: ставит выбранный символ палитры | `1` |
| Прямоугольник | drag: рамка, при отпускании — заливка прямоугольной области (в blocked — блокировка, в preset — выбранным символом) | `2` |
| Ластик | снимает клетки (blocked → free; preset → free) | `3` |
| Очистить всё | кнопка с диалогом подтверждения: маска → все клетки свободны | — |

Повторный клик кисти по уже заблокированной клетке снимает блокировку (toggle) — в
preset-режиме повторный клик тем же символом не отменяет клетку; отмена — ластиком или
кистью другим символом. Рисование drag'ом: клетки, по которым прошла ЛКМ.

### 3.3 Палитра preset-редактора (вводная №7)

Палитра строится **динамически** из `spec.types`: каждый тип — чип «символ + id типа
(+ name)», при выборе подсвечивается; выбранный символ — текущий цвет кисти.
Добавление/удаление типа в `TypesPanel` немедленно отражается в палитре:

- новый тип → новый чип (цвет назначается автоматически из фиксированной палитры
  из 20 различимых цветов по порядку добавления, коллизии исключаются алгоритмом);
- удалённый тип → чип исчезает; клетки preset этой категории остаются в маске как «чужие»
  символы и сразу подсвечиваются ошибкой V-MASK-PRESET ([05](./05-validation.md) §2).

### 3.4 Viewport: скролл, панорамирование, зум (вводная №5)

- Сетка произвольного размера; область canvas — viewport со смещением (`pan.x/y`) и
  масштабом (`zoom`); рендер — только видимые клетки (crop по rect'у).
- **Панорамирование**: средняя кнопка мыши drag, либо зажатый `Пробел` + ЛКМ; скроллбары
  контейнера синхронизированы.
- **Зум** (опция, но реализуется в v1): колесо мыши = зум к курсору, диапазон
  `[автоfit/4 … 32×]`; `0` — сброс на fit-to-screen; при z ≥ 8 отображается текст
  символа типа в клетке preset (в blocked-режиме символ не нужен).
- **Индикатор области видимости** («миникарта»):в правом нижнем углу — мини-превью всей сетки
  (отдельный небольшой canvas, ≤ 200 пикс по большей стороне) с рамкой текущего
  viewport; клик по миникарте — перемещение центра.
- **Координаты курсора**: строка статуса внизу: `x=17 y=42 · zoom 6× · клеток всего 50×50`.

### 3.5 Ошибки на сетке (связь с [05](./05-validation.md) §4)

- Клетки, участвующие в ошибке маски (недопустимый символ в preset — при чтении файла),
  обводятся красным пунктиром;
- если `blockedMask`/`presetMask` не совпадает размером с `grid` (внешний файл) — сетка
  НЕ рендерится из этого файла: показывается заглушка «Маска 10×10 ≠ сетка 50×50» и
  ошибка в баннере; редактирование маски в этом режиме заблокировано до исправления
  (смена grid или перезагрузка маски).

### 3.6 Ограничения canvas-редактора

Клетки, занятые preset'ом, **не можно заблокировать** маской блокировок и наоборот —
одна клетка не может быть одновременно `*` и preset'ом: в blocked-режиме клик по
preset-клетке игнорируется с подсказкой «Клетка занята preset-кластером (тип ROOM)».
Это правило отражает семантику docs/03 §2–§3 (клетка — либо блокировка, либо клетка
кластера, либо свободна).

### 3.7 Обработка указателя и горячие клавиши (спецификация)

**Hit-testing** (перевод экранных координат в клетку):

```
cellX = floor((clientX - canvasRect.left - pan.x) / cellPx)
cellY = floor((clientY - canvasRect.top  - pan.y) / cellPx)
cellPx = baseCellPx * zoom          # baseCellPx — размер клетки при zoom = fit
```

Клетка действительна, если `0 ≤ cellX < width` и `0 ≤ cellY < height`; иначе событие
игнорируется (клик вне сетки в blocked/preset-режиме ничего не делает; pan-жесты —
работают всюду).

**Поведение указателя:**

| Событие | Действие |
|---|---|
| ЛКМ down + drag (инструмент кисть/ластик) | рисование: каждая новая клетка под курсором обрабатывается один раз за stroke (мультименжество); toggle-поведение кисти (§3.2) применяется только на одиночном клике без движения |
| ЛКМ down + drag (прямоугольник) | рамка выделения от клетки старта до текущей; commit — на mouseup |
| МЛК down + drag / `Пробел`+ЛКМ | панорамирование (изменение `pan`), инструменты не срабатывают |
| Колесо мыши | зум к позиции курсора (§3.4): `pan' = cursor - (cursor - pan) * (zoom'/zoom)` |
| Правая кнопка | контекстное меню браузера отключено на canvas (`preventDefault`); действий не выполняет |

**Горячие клавиши** (действуют, когда фокус — на canvas/странице, не в текстовом поле):

| Клавиша | Действие |
|---|---|
| `1` / `2` / `3` | кисть / прямоугольник / ластик |
| `B` / `P` | режим «Маска блокировок» / «Preset-кластеры» (если маска загружена) |
| `0` | zoom = fit-to-screen |
| `+` / `-` | зум ×1.25 / ÷1.25 к центру viewport |
| `Ctrl/Cmd + Z` | не действует (undo вне v1, [07](./07-nfr-limits.md) §4 п.3) — подсказка при нажатии: «Undo появится в следующей версии» |

**Производительность рисования:** stroke-клетки применяются к модели немедленно,
а перерисовка canvas — батчами через `requestAnimationFrame` (не более одного редraw
на кадр); при drag через 1000 клеток за stroke подсказка «Большая область» не показывается
(ограничений на размер stroke нет).

## 4. Панель кластеров (`ClustersPanel`, таб «Кластеры»)

```
┌──────────────────────────────────┐
│ КЛАСТЕРЫ          [＋ Добавить]  │
├──────────────────────────────────┤
│ room1    ROOM1   26%   free  ✎ ✕ │
│ room2    ROOM2   15%   free  ✎ ✕ │
│ corridor1 CORRIDOR 10% circle ✎ ✕│
├──────────────────────────────────┤
│ Сумма долей: 51 % (≤ 100)        │  ← жёлтая при > 100 (ошибка V-CLUST-SUM)
└──────────────────────────────────┘
```

Форма «Добавить/Редактировать» (модальный):

| Поле | Тип | Валидация (см. [05](./05-validation.md)) |
|---|---|---|
| `id` | текст, уникален в списке | V-CLUST-ID: не пустой, уникален; латиница/цифры/`_`/`-` (рекомендация docs/03 — человекочитаемый id) |
| `type` | выпадающий список из `types` | обязателен тип; V-CLUST-TYPE при указании несуществующего (в UI недостижимо, защита на уровне модели) |
| `areaPercent` | число (0..100], до 2 знаков после запятой | вне диапазона — форма не сохраняет (проверка формы, [05](./05-validation.md) §2.4); сумма по списку — V-CLUST-SUM |
| `shape` | free / rectangle / circle (радиокнопки) | V-SHAPE; подсказка под полем — однострочные описания из docs/03 §4 |

Удаление (`✕`) — с подтверждением. Порядок в списке = порядок сериализации
([02](./02-data-model-formats.md) §2); перетаскивание строк — опция v1 (не входит).

## 5. Панель типов (`TypesPanel`, таб «Типы»)

```
┌──────────────────────────────────┐
│ ТИПЫ                [＋ Добавить]│
├──────────────────────────────────┤
│ R │ ROOM1    │ Комната-1   ✎ ✕  │
│ W │ ROOM2    │ Комната-2   ✎ ✕  │
│ C │ CORRIDOR │ Коридор     ✎ ✕  │
└──────────────────────────────────┘
```

Форма: `id типа` (ключ реестра; уникальный, латиница/цифры/`_`), `symbol` — **один
символ**, `name` (необязательный текст). Валидация:

- дубликат symbol среди типов → блокируется (V-TYPE-SYMDUP);
- символ `.` или `*` → блокируется (зарезервированы docs/03 §2, ASCII-карта) — V-TYPE-RESERVED;
- пустой symbol / length ≠ 1 → блокируется.

**Удаление типа:** если тип используется (`clusters[].type` ссылается или в preset-маске
есть клетки этого символа) — диалог: «Тип ROOM2 используется кластерами [room2] и
preset-клетками (37 шт.). Варианты: (1) отменить; (2) удалить тип, а также связанные
кластеры и preset-клетки». Второй вариант выполняет каскад. Без ссылок — удаление
немедленное с подтверждением.

## 6. Панель правил (`RulesPanel`, таб «Правила»)

| Секция | Поля | Примечание |
|---|---|---|
| Связность | индикатор `connectivity: 8` (read-only, [02](./02-data-model-formats.md) §2) | текущий срез — 8 |
| Соседство: Запрещённые пары | список пар + форма «тип A» × «тип B» → «Добавить»; удаление пары | пары неупорядоченные (A×B = B×A), дубликаты блокируются; типы из выпадающих списков реестра (V-ADJ-TYPE недостижимо в UI) |
| Соседство: Whitelist | переключатель «Только разрешённые пары (allow)» + тот же список пар при включении | выкл = `allow: null` (default-open); вкл → массив пар; подсказка с семантикой docs/04 §2 |
| Размер | `min`, `max` — числа ≥ 0 или пусто (`null`) | жёсткие границы, docs/04 §3; ошибка если min > max (V-SIZE) |
| Выпуклость | индикатор `soft` (read-only); подпись «hard — зарезервировано» | docs/04 §5 |
| Заполнение площади | чекбокс `fillAll` | подсказка: docs/03 §1 / docs/04 §6 |
| Примыкание всех кластеров | чекбокс `touchAll` | подсказка: «все кластеры обязаны примыкать друг к другу (единый ком)» — docs/04 §9 |

## 7. Валидация на лету

- Пересчёт `validateAll(state)` ([05](./05-validation.md)) — на каждое изменение модели
  (debounce 300 мс); результат: список ошибок в `ValidationBanner` (левая колонка, §1) +
  подсветка на сетке (§3.5) + неактивность кнопок скачивания при наличии ошибок **масок**
  (спеку скачивать можно — но с подтверждением «есть N ошибок; скачать как есть?»).
- Ошибки нумеруются кодами V-* из [05](./05-validation.md) §2; текст ошибки — на русском,
  с указанием поля/клеток (например, «Preset: клетка (12, 7) содержит символ "X", не
  совпадающий ни с одним типом»).

## 8. Служебные элементы

- Строка статуса внизу центрального блока: координаты курсора, zoom, размер сетки (§3.4).
- `beforeunload`-предупреждение при несохранённых изменениях (refresh = потеря,
  [07-nfr-limits](./07-nfr-limits.md) §2): «Есть несохранённые изменения — скачайте файлы».
- Маркер «изменено»: после любого изменения модели у кнопок скачивания появляется точка
  (indicates dirty); сбрасывается после скачивания соответствующего файла.
