# 06. Тестирование и критерии приёмки

> Сводный индекс: [../docs-editor/README.md](./README.md) · Архитектура (слои):
> [01-architecture](./01-architecture.md) §2.4 · Валидация: [05-validation](./05-validation.md)

## 1. Уровни тестирования

| Уровень | Инструмент | Что покрывает | Где |
|---|---|---|---|
| Unit | Vitest | чистые модули `lib/`: specYaml, maskText, validation | `editor/tests/unit/` |
| Компонентный | Vitest + React Testing Library (опционально в v1, минимум: FilesPanel-статусы) | связка UI ↔ state | `editor/tests/unit/` |
| E2E | Playwright (Chromium; Firefox/Safari — ручная приёмка) | сквозные сценарии §3 | `editor/tests/e2e/` |

Требование: unit-тесты не используют браузер и DOM (чистые функции), время полного
прогона unit < 30 с.

## 2. Unit-тесты (Vitest)

### 2.1 Сериализатор спеки (`specYaml`)

- round-trip: `dumpSpec(parseSpec(y))` по эталонным файлам `examples/spec_basic.yaml`,
  `examples/spec_touchall.yaml`: **эквивалентность данных** — `parseSpec(dumped)` глубокоравен
  исходной модели (комментарии не сохраняются — [02](./02-data-model-formats.md) §4, п.1);
- порядок ключей: строка dump'а начинается с `grid:`, затем `blockedFile:`, `presetFile:`,
  `types:`, `rules:`, `clusters:` (проверка построчно, [02](./02-data-model-formats.md) §2);
- стиль: `symbol` в двойных кавычках; `null`; `[]`; пары adjacency `[A, B]`; отступ 2 пробела;
- дефолты парсинга: YAML без `touchAll` → модель `touchAll: false`; на dump — поле прописано явно;
- числа: `areaPercent: 12.5` round-trip'ится как `12.5`; `30` → `30` (не `30.0`).

### 2.2 Маски (`maskText`)

- **Round-trip побайтовый** на эталонах: `dumpMask(parseBlockedMask(examples/blocked_basic.txt, 10, 10)) === исходный текст` и аналогично `preset_example.txt`;
- терпимость чтения: строки с пробелами/`-` парсятся как free; при dump — канонически `.` ([02](./02-data-model-formats.md) §5);
- ошибки: файл 9 строк на grid 10 → V-MASK-DIM с фактическим размером в сообщении;
- preset: символ, не совпадающий ни с одним типом → V-MASK-PRESET, клетки в `cells[]`.

### 2.3 Валидатор (`validation`) — таблица соответствия [05](./05-validation.md) §4

Для **каждого** кода V-GRID-DIMS, V-MASK-DIM, V-CLUST-TYPE, V-CLUST-ID, V-CLUST-SUM,
V-ADJ-TYPE, V-SHAPE, V-TOUCHALL-TYPE: тест с невалидной моделью → код присутствует в
результате; и парный эталон — тот же YAML отклоняется `space_manager` (exit 2) — эталоны
хранятся в `tests/fixtures/bad-specs/` и используются в §3.3.

### 2.4 Палитра и каскады

- добавление типа → новый символ палитры, без коллизий цветов; удаление типа с
  preset-клетками → клетки помечаются ошибкой V-MASK-PRESET (симуляция состояния);
- каскад удаления типа: кластеры и пары adjacency этого типа удаляются.

## 3. E2E-сценарии (Playwright)

### 3.1 Загрузка и round-trip без изменений

Загрузить `examples/spec_basic.yaml` + `examples/blocked_basic.txt` → скачать оба файла
(без правок) → сравнить: маска побайтово; спека — эквивалентность данных (через
`js-yaml.load` в тесте). **Ожидание: PASS без единой ошибки валидации.**

### 3.2 Редактирование маски и скачивание

Загрузить пару из §3.1 → режим «Маска блокировок» → кистью заблокировать клетку (5,5)
и снять клетку (0,0) → скачать маску → в скачанном тексте: позиция (5,5) = `*`,
(0,0) = `.`, остальные клетки без изменений.

### 3.3 Совместимость со space-manager (ключевой сквозной тест)

Скачанные файлы §3.1–§3.2 копируются в temp-каталог; запускается:
`python -m space_manager place <spec>`. **Ожидание:** exit 0 и карта в stdout для
валидного результата; для каждого файла из `tests/fixtures/bad-specs/` (по коду V-*) —
exit 2. Тест выполняется при установленном Python-окружении проекта (CI: шаг
`pip install -e .`); если окружение недоступно — тест маркируется `@integration` и
прогоняется при ручной приёмке (§5).

### 3.4 CRUD кластеров/типов/правил

Добавить кластер (id, type, areaPercent=10, shape=rectangle) → строка в списке; сумма
долей пересчитана; изменить `fillAll` на true → скачать спеку → в YAML `fillAll: true`;
добавить запрещённую пару типов [A, B] → в YAML `forbidden: [[A, B]]`; удалить тип с
каскадом → связанные кластеры/пары/preset-клетки обработаны по 04 §5.

### 3.5 Валидация на лету

Ввести `areaPercent` так, чтобы сумма > 100 → в баннере ошибка V-CLUST-SUM;
загрузить preset с чужим символом → клетки подсвечены (проверка по canvas: цвет пикселя
рамки), скачивание маски требует подтверждения.

### 3.6 Viewport

Спека 200×200 → сетка отображается целиком при fit; зум ×8 к курсору — клетки
увеличены, символы типов видны; панорамирование средней кнопкой перемещает viewport
(проверка по смещению миникарты); координаты курсора в строке статуса обновляются.

## 4. Критерии приёмки по экранам (сводка)

| Экран/функция | Критерий |
|---|---|
| Панель файлов | §3.1–§3.2; статусы файлов корректны; порядок «спека первой» соблюдён; предупреждение о потере изменений при перезагрузке спеки |
| Canvas blocked-режим | кисть/прямоугольник/ластик/очистка работают; preset-клетки не блокируются (§3.6 04); drag-рисование непрерывное |
| Canvas preset-режим | палитра = текущие типы (вводная №7); рисование выбранным символом; заблокированные клетки — серым фоном, не редактируемы |
| Viewport | §3.6; миникарта с рамкой; координаты курсора |
| Кластеры | CRUD + форма по 04 §4; сумма долей; удаление с подтверждением |
| Типы | CRUD; symbol-конфликты блокируются (дубль/`.`/`*`); каскад удаления |
| Правила | adjacency forbidden/allow, size, fillAll, touchAll — изменения попадают в YAML (§3.4) |
| Валидация | §3.5; все коды V-* из 05 §2 имеют UI-представление (баннер + сетка) |

## 5. Ручной чек-лист приёмки (выполняется заказчиком)

- [ ] `cd editor && npm install && npm run build && npm start` → http://localhost:3000 открывается.
- [ ] Загрузить `examples/spec_basic.yaml`, `examples/blocked_basic.txt`, `examples/preset_example.txt` — все статусы «загружена», ошибок нет.
- [ ] Отредактировать маску блокировок (кисть + прямоугольник) и preset (2 типа из палитры), скачать оба файла — тексты корректны.
- [ ] Скачать спеку → `python -m space_manager place <spec>` → exit 0, карта в stdout.
- [ ] Создать спеку с нуля 200×200 → нарисовать блокировки и preset → плавное панорамирование/зум (без подтормаживаний).
- [ ] Намеренно сломать: сумма долей 110, дубликат symbol, маска другого размера — все три ошибки видны в баннере.
- [ ] Refresh страницы при несохранённых изменениях → предупреждение браузера.
- [ ] Откройте в Chrome, Firefox, Safari — поведение идентично (§3 Playwright покрывает Chromium; остальные два — визуально).

## 6. Производительность (критерии, детали — [07-nfr-limits](./07-nfr-limits.md) §3)

| Сценарий | Целевое значение |
|---|---|
| Панорамирование/зум сетки 200×200 | ≥ 30 FPS (замер: `requestAnimationFrame`-счётчик, e2e §3.6 пометкой) |
| Отклик на клик (клетка перекрашена) | ≤ 100 мс от pointerdown до перерисовки |
| Полная перерисовка 200×200 при зуме | ≤ 50 мс |
| Загрузка SPA (prod-сборка, localhost) | первая рендеризация ≤ 2 с |
